# Проект sample (whiteEditor)

Игра на three.js, которая собирается в редакторе whiteEditor. Весь проект — текстовые файлы в этой папке;
их можно править руками или агентом, редактор подхватывает изменения с диска без перезагрузки.

## Структура

| Путь | Что это |
|---|---|
| `scenes/<имя>.json` | Сцены (уровни) |
| `materials/<имя>.json` | Материалы |
| `prefabs/<имя>.json` | Префабы |
| `terrains/<имя>.json` | Рельеф: сетки высот для компонента `terrain` (см. «Рельеф») |
| `biomes/<имя>.json` | Биомы: виды земли для генератора рельефа (см. «Рельеф», «Биом») |
| `looks/<имя>.json` | Стили рендера (Look): пиксели, поверхности (дрожание вершин, toon-свет), контуры, палитра и другие экранные эффекты |
| `scripts/**/*.ts` | Код: модели, собранные кодом, поведения объектов, свои экранные эффекты, поверхности и небо, клипы анимации и аниматоры |
| `assets/` | Файлы: текстуры, звук, шрифты, модели glTF (`.glb`) |
| `folders.json` | Папки панели Project редактора — только раскладка, см. ниже. Файла может не быть |
| `project.json` | Настройки проекта: слои столкновений (см. «Столкновения»). Файла может не быть |
| `renders/` | Картинки сцен от команды `render`; в git не попадают |

Имена файлов сцен, материалов, префабов, стилей и рельефа — только латиница, цифры, `_` и `-`.

Папки в панели Project редактора — только раскладка: файлы остаются на местах (`materials/Bricks.json`),
имена уникальны на весь проект, ссылки — по имени, как и раньше. Что в какой папке лежит, записано в
`folders.json`:

```json
{
  "materials": { "Walls": ["Bricks", "Stone"] },
  "scenes": { "Levels": ["main"] }
}
```

Разделы: `scenes`, `materials`, `prefabs`, `looks`, `terrains`, `biomes`, `textures`, `sounds`, `models` (для текстур, звуков и файлов
моделей имя — с расширением: `"bricks.png"`, `"coin.wav"`, `"robot.glb"`; модель из кода — по имени из `defineModel`). Папка в папке — путь в имени: `"Walls/Old"`. Ассет, не названный ни в одной папке, лежит наверху;
имя, которого в проекте нет, пропускается. На игру и сборку файл не влияет.

## Общее для всех проектов

Рядом лежит проект `shared` (`projects/shared/`, обычный проект): его стили (`looks/`) и всё, что определено в его
`scripts/` — экранные эффекты, поверхности, поведения, модели, — есть в каждом проекте, копировать их не нужно.
Сцена называет общий стиль (`"look": "PixelArt"`) или поведение (`"script": "spin"`) так же, как своё. Что есть
сейчас — смотрите в `projects/shared/looks/` и `projects/shared/scripts/`.

- Своё с тем же именем перекрывает общее: `looks/PixelArt.json` в проекте заменяет общий `PixelArt` только для
  этого проекта (в редакторе правка общего стиля сама делает такую копию); то же с поведением, эффектом,
  поверхностью и моделью из `scripts/`.
- Нужное нескольким играм кладите в `shared`, нужное одной — в неё. Правка в `shared` меняет все проекты.
- Материалы, префабы, сцены, рельеф (`terrains/`), файлы `assets/` и `project.json` у каждого проекта свои.
- `check`, `render` и сборка игры берут общее сами; в собранную игру оно попадает целиком.

## Проверка

Из корня whiteEditor (на две папки выше):

```bash
npm run check -- sample
```

Команда проверяет все сцены, префабы и стили (неизвестные компоненты, эффекты, поверхности и поля, типы значений, ссылки
на материалы, модели, поведения, префабы и стили) и типы скриптов. Браузер для этого не нужен. Запускайте её после каждой правки файлов.

Каждую сцену без ошибок команда ещё и запускает на секунду игры без картинки: исключение в `start` или `update`
поведения — это ошибка `check` («in a run of 1 s»). Сцена, которой нужен браузер (поведение трогает `document`),
так не проверяется — команда назовёт её; `--no-run` пропускает запуск совсем. Шейдеры эффектов и поверхностей
`check` не компилирует — это делает `render`.

## Что сейчас в редакторе

```bash
npm run editor [-- --scene] [--json]
```

Печатает, что показывает открытый редактор: проект, сцену, есть ли **несохранённые правки** (тогда файл на диске
старее того, что видит автор, — не перезаписывайте сцену, не спросив), что выбрано, идёт ли Play и последние
сообщения Console (ошибки поведений и шейдеров попадают туда). `--scene` добавляет несохранённую сцену целиком,
как она была бы записана; `--json` — всё в JSON по каждой открытой странице редактора. Нужен запущенный
dev-сервер редактора; команда только читает.

## Картинка сцены

```bash
npm run render -- sample [сцена] [--out файл.png] [--size 960x540] [--time 2]
    [--camera x,y,z --target x,y,z [--fov 60]] [--look Имя | --no-look]
    [--input "KeyD@0-1.5 Space@1 click:Play@2"] [--state]
```

Рисует сцену в PNG так же, как её рисует игра (камера сцены, её Look), и кладёт в `renders/<сцена>.png` этой
папки. Редактор для этого не нужен: команда сама на секунду запускает Chrome или Edge без окна. Откройте
картинку, чтобы увидеть результат правок сцены, материалов, стиля или шейдера.

| Опция | Что делает |
|---|---|
| `--out` | куда записать картинку |
| `--size` | размер в пикселях, по умолчанию `960x540` |
| `--time` | сколько секунд сцена «играет» до снимка: поведения двигают объекты, эффекты видят это `time` |
| `--camera`, `--target`, `--fov` | смотреть из точки `--camera` на точку `--target` вместо камеры сцены |
| `--look`, `--no-look` | нарисовать с другим стилем или без стиля, не меняя файл сцены |
| `--input` | сыграть сцену с этими нажатиями (см. ниже) |
| `--state` | напечатать, где после этого каждый объект и что написано в текстах интерфейса |

**Проверка игры, а не только картинки.** `--input` — что делает игрок, через пробел, каждое `<что>@<когда>`
(секунды от старта сцены):

| Запись | Что значит |
|---|---|
| `KeyD@0-1.5` | клавиша зажата с 0 до 1.5 с (имена — как в `self.input`: `KeyW`, `Space`, `Pad0`) |
| `Space@1` | короткое нажатие в 1 с |
| `click:Play@2` | щелчок по объекту с именем `Play`: по середине его элемента интерфейса или по месту объекта на экране |
| `click:0.5,-0.2@2` | щелчок по точке экрана (от −1 до 1, как `mouseX` / `mouseY`) |
| `mouse:0.5,0@1` | мышь переходит в точку (или `mouse:Имя@1` — на объект) |
| `Mouse2@1-2` | зажата правая кнопка мыши |
| `type:Ann\n@1` | текст с клавиатуры — в поле ввода, по которому до этого щёлкнули; `_` — пробел, `\n` — Enter, `\b` — Backspace |

Сцена играет `--time` секунд; без `--time` — столько, сколько нужно на все нажатия. `--state` печатает строку на
объект: имя, место в мире, `inactive` у выключенных, текст компонента `text` — и `self.globals`. То, что
скрипты пишут в `console.log`, печатается всегда. Так проверяют поведение после правки:

```bash
npm run render -- sample iso --input "KeyD@0-1" --state
#   state: Player  [1, 0.5, 2]      <- был в [-2, 0.5, 2]: за секунду проехал 3 метра
npm run render -- sample ui --input "click:Add@0.2 click:Add@0.6" --state
#   state: Score  [0, 0, 0]  text "Score: 2"
```

Кадры идут ровно по 1/60 с, поэтому результат один и тот же от запуска к запуску (если поведения не берут
`Math.random`). Переход `self.loadScene` в прогоне выполняется, как в игре: команда пишет, в какую сцену он пришёл, а картинка и
`--state` — уже этой сцены; так одной командой проходят игру из нескольких сцен (`click:Play@0.3` в меню, дальше
клавиши уровня). Звук не играет.

Если в сцене нет камеры и `--camera` не задана, камера ставится сама так, чтобы вся сцена попала в кадр.
Команда печатает проблемы, найденные по ходу, — ошибки компиляции шейдеров (эффектов и поверхностей),
исключения в поведениях, несуществующий Look — и тогда завершается с кодом 1; картинка при этом всё равно пишется.

## Сборка игры

```bash
npm run build:game -- sample [сцена] [--no-check]
```

Собирает игру в `build/` этой папки: `index.html` и `game.js`, открывается в браузере прямо с диска.
В игру попадают все сцены проекта: поведение переходит из одной в другую через `self.loadScene("имя")`.
Стартует она с указанной сцены; без неё — со `startScene` из `project.json`, иначе с `main`, иначе с первой по
алфавиту. Игра смотрит через камеру сцены — без активного объекта с компонентом `camera` на экране ничего не
будет. Перед сборкой команда сама запускает `check` и проект с ошибками не собирает (`--no-check` — собрать
всё равно). Папку `build/` руками не правят.

## Настройки проекта

`project.json` в корне проекта; файла и любого поля может не быть.

```json
{
  "startScene": "menu",
  "aspect": "16:9",
  "gravity": 20,
  "tags": ["player", "enemy"],
  "layers": ["Player", "Enemy", "Pickup"],
  "noCollision": [["Enemy", "Pickup"]]
}
```

| Поле | Что это |
|---|---|
| `startScene` | сцена, с которой стартует собранная игра |
| `aspect` | форма картинки игры: `"free"` (на всё окно), `"16:9"`, `"16:10"`, `"4:3"`, `"1:1"`, `"9:16"`; остальное окно чёрное |
| `gravity` | ускорение падения тел физики, м/с²; по умолчанию 20, как у `self.fall` (см. «Физика») |
| `bottom` | дно мира, метры: тело физики, упавшее ниже, убирается из сцены; по умолчанию −100 |
| `pushMass` | тело тяжелее этого (кг) объект, который ходит через `self.move`, не сдвигает — упирается, как в стену; 0 (по умолчанию) — расталкивает любые |
| `tags` | теги проекта. Если список есть, тег объекта не из него — ошибка `check`; без списка тегом может быть любое слово |
| `layers`, `noCollision` | слои столкновений, см. «Столкновения» |

## Сцена

```json
{
  "version": 3,
  "environment": { "fog": true, "fogColor": "#0b4a5c" },
  "entities": [
    {
      "name": "Floor",
      "scale": [20, 1, 20],
      "components": [{ "type": "mesh", "shape": "plane", "material": "Concrete" }]
    },
    {
      "name": "Lamp",
      "position": [0, 3, 0],
      "components": [{ "type": "light", "kind": "point", "intensity": 10 }],
      "children": [
        { "name": "Shade", "components": [{ "type": "mesh", "shape": "cylinder" }] }
      ]
    }
  ]
}
```

Объект сцены (entity) — пустой контейнер, как GameObject в Unity; всё, что он рисует и делает, дают компоненты.

| Поле | Значение | По умолчанию |
|---|---|---|
| `name` | имя, по нему объект ищут в коде | `"GameObject"` |
| `id` | любая строка, уникальная в сцене; можно не писать — редактор создаст | — |
| `active` | `false` скрывает объект вместе с детьми | `true` |
| `tag` | любое слово, по которому объект находят в игре: `self.findAll({ tag: "enemy" })`; у экземпляра без своего тега — тег корня префаба | — |
| `prefab` | имя префаба: объект — его экземпляр (см. «Префаб») | — |
| `overrides` | только у экземпляра: что он меняет внутри префаба (см. «Префаб») | — |
| `position` | `[x, y, z]`, метры, относительно родителя | `[0, 0, 0]` |
| `rotation` | `[x, y, z]`, градусы, углы Эйлера XYZ | `[0, 0, 0]` |
| `scale` | `[x, y, z]` | `[1, 1, 1]` |
| `components` | список компонентов, не больше одного каждого типа (кроме `script`) | `[]` |
| `children` | дочерние объекты | `[]` |

Любое поле со значением по умолчанию можно не писать. Ось Y — вверх. Свет и камера смотрят вдоль своей
локальной оси −Z, направление задаётся поворотом объекта.

## Рельеф (terrain)

`terrains/Hills.json` — земля мира: сетка высот. Имя файла без расширения — имя, на которое ссылается компонент
`terrain` (поля — в «Компонентах»).

```json
{
  "cell": 1,
  "heights": [
    [0, 0, 0, 0],
    [0, 1.5, 2, 0],
    [0, 2, 1.5, 0],
    [0, 0, 0, 0]
  ]
}
```

| Поле | Что это |
|---|---|
| `cell` | метры между соседними высотами, одинаково по X и по Z |
| `heights` | строки высот: строка идёт вдоль X, строки следуют друг за другом вдоль Z. Не меньше 2 строк по 2 числа, все строки одной длины, не больше 1025 на сторону |
| `palette` | виды земли цветами: `["#6f9a4a", "#8b8d8f"]` (трава, камень…), не больше 32. Можно не писать |
| `scatter` | пропсы на земле: копии префабов (см. ниже). Можно не писать |
| `rivers` | реки: линии точек, по которым в землю врезано русло с водой (см. ниже). Можно не писать |
| `biomes`, `biomeMap` | где какой биом лежит: список имён биомов и сетка того же размера, что `heights`, с номером биома из списка в каждой точке; `-1` — земля, которую не делал ни один биом (см. ниже). Можно не писать |
| `generator` | настройки генератора этой земли (см. ниже), например `{ "seed": 7, "height": 20 }`. Можно не писать |
| `colors` | чем покрашена земля: такая же сетка, как `heights`, в каждой точке — номер цвета в `palette` (с нуля). Можно не писать — тогда земля цвета материала |

Середина сетки стоит там, где объект; первое число первой строки — угол с наименьшими x и z. Высота — метры вверх
от объекта. Размер земли — число промежутков на `cell`: 65 чисел в строке при `cell` 1 — это 64 метра.

```json
{ "name": "Ground", "components": [{ "type": "terrain", "terrain": "Hills", "material": "Grass", "flat": true }] }
```

- `flat` — каждый треугольник освещён целиком, видны грани (под простые формы); без него земля гладкая.
  `textureSize` — сколько метров земли покрывает один повтор картинки материала. Без `terrain` (`""`) — ровный
  кусок 32 × 32 м.
- **Покраска.** С `palette` и `colors` земля покрашена по точкам сетки: между точками цвет переходит плавно, а с
  `flat` у каждого треугольника один цвет — смесь трёх его углов. Цвет умножается на материал, поэтому крашеной
  земле ставьте белый материал или никакого (`"material": ""` — тогда она белая под краской). Красить удобно
  правилом в скрипте: камень, где круто, песок в низинах, снег выше какой-то высоты.
- **Земля сплошная такой, какой нарисована**, `collider` ей не нужен: по ней ходят через `self.move` и
  `self.fall`, на ней лежат и катятся тела физики, в неё попадают лучи (`self.raycast` вернёт точку и нормаль
  склона), её касаются триггеры. `layer` — слой столкновений, как у коллайдера.
- Ходят по ней, как по склонам: только с `step` больше нуля (см. «Столкновения»), склон круче примерно 50° —
  стена. За краем земли опоры нет.
- **Не поворачивается и не масштабируется**: `rotation` и `scale` объекта с `terrain` должны быть `[0, 0, 0]` и
  `[1, 1, 1]` (иначе ошибка `check`), место задаёт `position`. Крупнее или мельче — другой `cell`.
- Несколько кусков ставят рядом: `position` соседа отличается на размер куска, а числа по общему краю у обоих
  одинаковые — тогда шва нет.
- Высоты большой земли руками не пишут: считайте их маленьким скриптом (шум, синусы, своя функция `h(x, z)`) и
  записывайте в файл, строку высот — в одну строку текста. Открытый редактор покажет правку файла сразу.
- **Пропсы (россыпь).** Деревья, камни, трава — тысячи копий нескольких префабов. Это не объекты сцены, а
  список в файле рельефа:

  ```json
  "scatter": [
    { "prefab": "Pine", "items": [[12.5, -3.2, 140, 1.1], [14.1, 2.7, 15, 0.9]] },
    { "prefab": "Rock", "items": [[-6, 8.4, 0, 2]] }
  ]
  ```

  Копия — четыре числа: `x` и `z` в метрах от середины рельефа, поворот вокруг вертикали в градусах и размер (во
  сколько раз больше префаба). Высоту не пишут: копия стоит на земле, где бы та ни была, и поднимается вместе с
  ней. Каждый префаб в списке один раз. От префаба у копии только вид (все его меши; все копии одного префаба
  рисуются разом) и сплошной `collider` **корня** префаба: в него упирается то, что ходит через `self.move`, и
  попадают лучи (`hit.object` — объект рельефа), и тела физики (`body`) тоже. Поведений, света, звука, частиц у копий нет; `enter` / `exit` на
  них не срабатывают, толкнуть копию нельзя. Нужен пропс с поведением (сундук, дверь) —
  ставьте его обычным объектом сцены. Расставлять сотни копий удобно скриптом: случайные точки, отсев по
  уклону и расстоянию до соседей.
- **Генератор.** В редакторе у компонента Terrain есть раздел Generate: холмы из шума по настройкам из поля
  `generator` файла — `seed` (зерно: другое число — другая земля), `height` (метры от низин до вершин), `size`
  (метры поперёк холма), `detail` (мелкие неровности, метры), `paint` (красить ли: камень, где уклон круче `rock`,
  песок ниже `sandBelow`, снег выше `snowAbove`, остальное трава — по номерам обычной палитры 2, 3, 4 и 0).
  Высота зависит только от настроек и места в мире, поэтому соседние куски с одинаковыми настройками
  сходятся без шва. Сами высоты в файле — уже готовый результат: поменяв `generator` руками, землю вы не
  измените, пока автор не нажмёт Generate (или пока вы сами не пересчитаете `heights`).
- **Биом** — вид земли: `biomes/Swamp.json`. Рельеф называет его в `"generator": { "biome": "Swamp", "seed": 7 }`,
  и тогда Generate (кнопка и кисть) делает землю по биому: форму, покраску и пропсы. Все поля необязательны:

  ```json
  {
    "base": -2, "height": 4, "size": 40, "detail": 0.3,
    "ground": "#4a5a32", "rock": "#6b6b60", "rockSlope": 0.8,
    "low": "#3a3326", "lowBelow": -2.5, "high": "#eef2f5", "highAbove": 100,
    "props": [
      { "prefab": "DeadTree", "spacing": 9, "cover": 0.6, "sizeMin": 0.8, "sizeMax": 1.4, "maxSlope": 0.4 },
      { "prefab": "Reeds", "spacing": 2, "cover": 0.4, "maxHeight": -2 }
    ]
  }
  ```

  `base` — на какой высоте лежит земля в целом (болото ниже нуля, плато выше), `height` / `size` / `detail` — холмы,
  как у генератора. Земля цвета `ground`; `rock` — где уклон круче `rockSlope`; `low` — ниже `lowBelow`; `high` — выше
  `highAbove` (цвета сами добавляются в палитру рельефа). `props` — что растёт: `spacing` — примерно метров между
  соседями, `cover` — какая доля земли ими занята (меньше 1 — рощи с полянами), `sizeMin` / `sizeMax`, не круче
  `maxSlope`, не ниже `minHeight` и не выше `maxHeight`. Пропсы биома встают вместо тех, что там стояли. Одно
  зерно и одно место в мире дают одну и ту же землю с теми же пропсами. Игре от биома нужен только его воздух (см.
  ниже): земля в ней — уже готовые `heights`, `colors` и `scatter` рельефа. Поменяв файл биома, землю вы не измените, пока её не
  сгенерируют заново.
- **Карта биомов.** Кисть Generate записывает в `biomeMap`, какой биом она положила. Кнопка Generate пересобирает
  землю по этой карте: каждую часть — её биомом, земля соседних биомов переходит одна в другую на `generator.blend` метрах (обычно 24; 0 — стык без перехода),
  покраска и пропсы — по биому места, а у границы — «языками» (место берёт биом точки в нескольких метрах в стороне). Земля с `-1` (сделанная руками или без биома) не меняется: биом рядом с
  ней сам подходит к её высоте. Чтобы разложить биомы файлом, напишите `biomes` и `biomeMap` и попросите автора
  нажать Generate.
- **Воздух биома.** Биом с `"air": true` имеет свой туман и свет, пока камера над его землёй (не выше 40 м над ней):
  `fogColor`, `fogNear`, `fogFar`, `ambientColor`, `ambientIntensity` и стиль `look` (пустой — стиль сцены). С `"sky": true`
  у неба сцены свои цвета `skyTop`, `skyHorizon`, `skyGround` (сверху, у горизонта, ниже горизонта), если небо у сцены есть;
  само небо остаётся тем же (три цвета или небо кодом, которое их получает), картинку неба `skyImage` цвета не меняют. Переход между
  соседними биомами — за 2 секунды (небо — несколькими шагами). Это слабая зона: `zone`, `water` и река, в которых стоит камера, важнее. Где какой
  биом, говорит `biomeMap` рельефа, поэтому файлы биомов нужны и в собранной игре (сборка их берёт сама).
- **Форма земли кодом.** Вместо обычных холмов рельеф (`"generator": { "shape": "terraces", "shapeParams": { "step": 3 } }`)
  или биом (те же поля `shape` и `shapeParams`) может назвать форму из `scripts/`:

  ```ts
  import { defineGenerator } from "white-engine";

  export const terraces = defineGenerator({
      name: "terraces",
      params: { step: { type: "number", default: 3, min: 0.5 } },
      // Метры над base. x, z — место в мире; hills — что дали бы обычные холмы (height, size, detail);
      // noise(x, z, octaves?, shift?) — гладкий шум 0..1 от зерна
      height: ({ x, z, hills, params, noise }) => Math.round(hills / params.step) * params.step + noise(x / 40, z / 40) * 2,
  });
  ```

  Функция должна давать одну и ту же высоту для одного места: землю делают по частям (кисть), а соседние рельефы
  должны сходиться. Покраска и пропсы биома идут как обычно, по получившейся форме. Земля меняется, когда её
  генерируют (кнопка или кисть Generate).
- **Реки.** Список в файле рельефа:

  ```json
  "rivers": [
    { "points": [[-60, 40, 12.5], [-20, 10, 9], [30, -5, 4.2], [80, -30, 0.5]], "width": 6, "depth": 1.2 }
  ]
  ```

  Точка — `[x, z, y]`: метры от середины рельефа и высота **поверхности воды** в этом месте; точки идут от истока к
  устью, между ними река плавно изгибается, а вода ровно спускается от высоты к высоте. Вверх вода не течёт: точка
  выше предыдущей считается на её уровне. Необязательные поля: `width` (метры от берега до берега, обычно 6),
  `depth` (метры воды в середине русла, 1.2), `bed` (цвет дна; красится только уже покрашенная земля), `color` и
  `opacity` воды, `flow` — метров в секунду течёт вода от истока к устью (обычно 1; 0 — стоячая). Течение видно (полосы
  бегут вниз по реке) и несёт: то, что плывёт через `self.swim`, и тела с `buoyancy`; `self.flow()` — куда и как быстро. Русло — часть высот: дно на `depth` ниже воды, берега на 0.3 м выше, склоны за берегами не
  круче 45° (через холм получается ущелье, через низину — насыпь), пропсы из воды убираются. Написав реку
  файлом, высот вы не измените: русло врезает редактор (кисть River, любое изменение реки) и генератор — после
  Generate реки остаются на месте. Чтобы врезать самому, пересчитайте `heights` (в движке — `applyRivers`).
  Удалённая река оставляет русло в земле. Вода реки ничего не останавливает; `self.submerged()` и вид из-под
  воды работают в ней так же, как в `water`.
- **Вода** — компонент `water` (поля — в «Компонентах») на отдельном объекте: ровная поверхность `sizeX` × `sizeZ`
  метров на высоте объекта. Всё, что ниже, — под водой; вода ничего не останавливает, по дну ходят как по
  земле. Пока камера под поверхностью (не глубже `depth`), сцена видна как под водой: туман цвета `underColor`
  с видимостью `visibility` метров, свет `underLight`, стиль `look`. Из поведения — `self.submerged(object?)`:
  на сколько метров объект под поверхностью (0 — не в воде): замедлить шаг, плыть, плеснуть. Плавать:
  `if (!self.swim(dt, 0.4)) self.fall(dt)` — в воде глубже 0.4 м объект не падает, а всплывает до этой глубины и
  держится на ней; на мели и на суше `swim` возвращает `false`, и объект падает как обычно. В реке плывущего несёт течение. Тело физики всплывает
  по полю `buoyancy` компонента `body`: 0 тонет, 1 висит в толще, 2 лежит на поверхности наполовину в воде.
  `waves` (метры от впадины до гребня), `waveLength` и `waveSpeed` — волны на поверхности; они только видны: глубина
  считается от ровной воды.

  ```json
  { "name": "Lake", "position": [0, -1.5, 0], "components": [{ "type": "water", "sizeX": 80, "sizeZ": 60, "depth": 10 }] }
  ```
- **Мир из кусков** — земля любого размера. Один кусок — обычный файл рельефа не больше 500 × 500 м, квадратный;
  все куски мира одного размера и называются по месту в сетке: `terrains/Big_0_0.json`, `Big_1_0.json`,
  `Big_-1_2.json` (имя мира, столбец вдоль X, ряд вдоль Z). Середина куска `i, j` — в `i · размер` метрах по X и
  `j · размер` по Z от объекта. Соседи делят высоты общего края: последний столбец `Big_0_0` равен первому столбцу
  `Big_1_0`, последняя строка `Big_0_0` — первой строке `Big_0_1` (иначе шов; `check` его найдёт). В сцене мир — один
  объект с компонентом `world` (поля — в «Компонентах»):

  ```json
  { "name": "Big World", "position": [-125, 0, -125], "components": [{ "type": "world", "world": "Big", "distance": 300, "detail": 150 }] }
  ```

  Показываются только куски ближе `distance` метров к камере (по горизонтали), остальные убираются, а в собранной
  игре их данные и не загружаются, пока камера не подойдёт: игра ждёт только кусок, на котором стоит камера.
  Куски дальше `detail` метров рисуются грубой сеткой (высота через 8, 4 или 2 клетки) без пропсов; столкновения и
  физика везде видят полную землю. Остальные поля — как у `terrain`, для всех кусков. Каждый кусок — рельеф
  со всеми его полями (покраска, пропсы, биомы, реки, `generator`); река живёт в одном куске (точки за его
  краем допустимы, но русло врезается только в этот кусок). Генератор считает высоту по месту в мире, поэтому
  куски с одинаковыми настройками сходятся сами. `rotation` и `scale` объекта — как у `terrain`.
- В редакторе землю правят кистью: кнопка Edit в заголовке компонента Terrain (поднять, опустить, сгладить,
  выровнять, покрасить) — мазок сразу пишется в этот же файл. Если автор сейчас работает кистью, не
  перезаписывайте файл рельефа целиком: его мазки пропадут.

## Look — стиль рендера

`looks/PixelArt.json`; имя файла без расширения — имя стиля. Сцена выбирает стиль полем `look` в
`environment`; редактор, Play и собранная игра рисуют через него одним и тем же кодом.

```json
{
  "pixelSize": 3,
  "surfaces": [
    { "surface": "toon", "steps": 3 }
  ],
  "effects": [
    { "effect": "outline", "lineColor": "#0a1a24" },
    { "effect": "palette", "levels": 6, "dither": 0.25 },
    { "effect": "grade", "contrast": 1.1 }
  ]
}
```

| Поле | Значение | По умолчанию |
|---|---|---|
| `pixelSize` | число (от 1 до 16) | `1` |
| `toneMapping` | `"none"` \| `"reinhard"` \| `"aces"` | `"none"` |
| `exposure` | число (от 0) | `1` |
| `pixelSnap` | `true` / `false` | `true` |
| `pixelUi` | `true` / `false` | `false` |
| `pixelText` | `true` / `false` | `false` |

`pixelSize` — во сколько раз уменьшается картинка перед увеличением «жёсткими» пикселями; 1 — полный размер.

Текст в крупных пикселях не читается, поэтому по умолчанию он остаётся чётким: интерфейс игры (см. «Интерфейс
игры») и надписи в мире (`label`) рисуются поверх готовой картинки в полном размере экрана, эффекты стиля их не
трогают. `pixelUi: true` рисует интерфейс в тех же крупных пикселях, что и картинка, `pixelText: true` — надписи
в мире (тогда на них действуют и эффекты). Картинки в мире (`sprite`) всегда в пикселях картинки.

`pixelSnap` действует с ортографической камерой (`camera.projection: "orthographic"`) и `pixelSize` больше 1:
камера сдвигается только на целые пиксели картинки, поэтому неподвижные объекты при её движении не мерцают, а
остаток сдвига добирается смещением готовой картинки. Для пиксель-арта с подвижной камерой берите
ортографическую камеру: с перспективной пиксели при движении «кипят».

`surfaces` — поверхности: добавки к материалам всех объектов сцены (куда встают вершины, как ложится свет) —
то, чего нельзя сделать с готовой картинкой. Запись — имя в `surface` и параметры, остальное как у эффектов.

`effects` — экранные эффекты, применяются по порядку сверху вниз. Запись — имя эффекта в `effect` и его
параметры; `"enabled": false` выключает эффект, не удаляя. Один эффект в списке — один раз.

`extends` — имя другого стиля, на котором построен этот: он получает его настройки, поверхности и эффекты,
а свои пишет поверх. Эффект (поверхность) с тем же именем остаётся на месте базового и получает новые
параметры, новый — добавляется в конец:

```json
{ "extends": "PixelArt", "effects": [{ "effect": "palette", "levels": 4 }, { "effect": "vignette" }] }
```

### Встроенные эффекты

### `outline` — Outline

| Поле | Значение | По умолчанию |
|---|---|---|
| `lineColor` | цвет `"#rrggbb"` | `"#101018"` |
| `thickness` | число (от 0.5 до 4) | `1` |
| `depth` | число (от 0) | `0.15` |
| `normal` | число (от 0 до 2) | `0.9` |
| `opacity` | число (от 0 до 1) | `1` |

### `palette` — Palette

| Поле | Значение | По умолчанию |
|---|---|---|
| `colors` | список цветов `["#rrggbb", ...]`, не больше 32 | `[]` |
| `levels` | число (от 2 до 32) | `5` |
| `dither` | число (от 0 до 1) | `0.3` |

### `grade` — Color Grade

| Поле | Значение | По умолчанию |
|---|---|---|
| `brightness` | число (от 0) | `1` |
| `contrast` | число (от 0) | `1` |
| `saturation` | число (от 0) | `1` |
| `tint` | цвет `"#rrggbb"` | `"#ffffff"` |

### `vignette` — Vignette

| Поле | Значение | По умолчанию |
|---|---|---|
| `strength` | число (от 0 до 1) | `0.5` |
| `radius` | число (от 0 до 1) | `0.6` |

### `glow` — Glow

| Поле | Значение | По умолчанию |
|---|---|---|
| `threshold` | число (от 0 до 4) | `0.8` |
| `strength` | число (от 0 до 4) | `1` |
| `radius` | число (от 1 до 48) | `8` |

### `ao` — Ambient Occlusion

| Поле | Значение | По умолчанию |
|---|---|---|
| `radius` | число (от 0.05 до 5) | `0.5` |
| `strength` | число (от 0 до 3) | `1` |
| `tint` | цвет `"#rrggbb"` | `"#000000"` |

### `smooth` — Smooth Edges

| Поле | Значение | По умолчанию |
|---|---|---|
| `threshold` | число (от 0.02 до 0.5) | `0.1` |

`palette` с непустым `colors` заменяет каждый пиксель ближайшим цветом из списка (`levels` тогда не
действует); с пустым — оставляет `levels` ступеней на канал. `dither` в обоих случаях прячет границы узором.

Толщина контура и `resolution` считаются в пикселях уменьшенной картинки (после `pixelSize`).

### `vertexSnap` — Vertex Snap

| Поле | Значение | По умолчанию |
|---|---|---|
| `size` | число (от 0.5 до 16) | `1` |

### `toon` — Toon Shading

| Поле | Значение | По умолчанию |
|---|---|---|
| `steps` | число (от 1 до 8) | `3` |
| `range` | число (от 0.05) | `1` |
| `softness` | число (от 0 до 1) | `0.05` |

### `flat` — Flat Faces

Параметров нет.

`vertexSnap` — дрожание вершин в духе PS1: вершины встают только на сетку пикселей уменьшенной картинки, поэтому
заметно вместе с `pixelSize` больше 1. `toon` делит свет на `steps` ровных полос от 0 до `range`; если
картинка стала слишком тёмной или вся в одной полосе — подбирайте `range` под яркость света в сцене.
`flat` освещает каждый треугольник как плоскую грань.

## Префаб

Префаб — объект вместе с детьми, сохранённый для повторного использования: `prefabs/Workplace.json`.

```json
{
  "version": 3,
  "root": {
    "name": "Workplace",
    "children": [
      { "name": "Desk", "scale": [1.6, 0.05, 0.7], "position": [0, 0.75, 0], "components": [{ "type": "mesh" }] },
      { "name": "Lamp", "position": [0.6, 0.8, 0], "components": [{ "type": "light", "kind": "point" }] }
    ]
  }
}
```

`root` — обычный объект сцены. Его `position` не используется, а `rotation` и `scale` получает новый
экземпляр при создании в редакторе.

Экземпляр в сцене — объект с полем `prefab`. У него свои `name`, `active`, `position`, `rotation` и `scale`;
компоненты и дети берутся из файла префаба, собственных `components` и `children` у экземпляра быть не должно:

```json
{ "name": "Workplace (2)", "prefab": "Workplace", "position": [3, 0, 0], "rotation": [0, 90, 0] }
```

### Переопределения в экземпляре

Экземпляр может изменить то, что даёт префаб, только для себя — полем `overrides`. Ключ — путь из имён от
корня префаба (`"Desk"`, `"Desk/Lamp"`); `"."` — сам корень. Значение — что заменить:

```json
{
  "name": "Workplace (2)",
  "prefab": "Workplace",
  "position": [3, 0, 0],
  "overrides": {
    "Desk": { "scale": [2, 0.05, 0.7], "components": { "mesh": { "material": "Wood" } } },
    "Lamp": { "active": false },
    ".": { "components": { "script:spin": { "params": { "speed": 30 } } } }
  }
}
```

| Поле | Что это |
|---|---|
| `active`, `position`, `rotation`, `scale` | заменяют значения объекта из префаба; у корня (`"."`) их нет — это поля самого экземпляра |
| `components` | по ключу компонента (`"mesh"`, `"light"`, для поведений `"script:<имя>"`) — поля, которые заменить; `params` заменяются по одному параметру |
| `addComponents` | список компонентов, которых у этого объекта в префабе нет: `[{ "type": "collider" }]`. Их поля меняют прямо здесь, а не через `components` |
| `removeComponents` | список ключей компонентов префаба, которых у этого объекта в экземпляре нет: `["mesh", "script:spin"]` |
| `addChildren` | список объектов, которых в префабе нет: они встают детьми после тех, что даёт префаб. Обычные объекты сцены, пишутся целиком (со своими `components` и `children`, могут быть экземплярами префабов) |
| `name` | другое имя объекта в этом экземпляре. Пути в `overrides` по-прежнему пишут по имени из префаба |
| `removed` | `true` — этого объекта префаба со всем, что под ним, в экземпляре нет; у корня (`"."`) нельзя |

```json
{
  "name": "Workplace (3)",
  "prefab": "Workplace",
  "overrides": {
    "Desk": {
      "addComponents": [{ "type": "collider", "sizeY": 0.05 }],
      "addChildren": [
        { "name": "Cup", "position": [0.3, 1, 0], "scale": [0.1, 0.1, 0.1], "components": [{ "type": "mesh", "shape": "cylinder" }] }
      ]
    },
    "Lamp": { "removed": true }
  }
}
```

Добавленное принадлежит экземпляру: путей к добавленному объекту и внутрь него в `overrides` нет — его
меняют прямо в `addChildren`, а убирают, удалив из списка. Имя добавленного объекта не должно совпадать с
именем соседа из префаба. `removed` и `removeComponents` относятся только к тому, что пришло из префаба.
Путь может уходить внутрь
экземпляра другого префаба, стоящего в этом (`"Shelf/Box"`). Если в префабе объект переименовали или убрали,
`check` сообщит, что по такому пути ничего нет. Имена соседних объектов в префабе должны различаться, и в них
не должно быть `/`. В редакторе добавленный объект получает id вида `"<id того, в чём он лежит>/<имя>"` и
пишет его в файл; руками `id` можно не писать.

Правка файла префаба меняет все его экземпляры во всех сценах (кроме того, что экземпляр переопределил). Внутри префаба могут стоять экземпляры
других префабов, но префаб не может содержать сам себя.

## Скрипты

Каждый `defineModel`, экспортированный из любого файла в `scripts/`, появляется в редакторе в панели Project.

```ts
import * as THREE from "three";
import { defineModel } from "white-engine";

export const pillar = defineModel({
    name: "pillar",
    label: "Pillar",
    params: {
        height: { type: "number", default: 3, min: 0.1, step: 0.1 },
        color: { type: "color", default: "#bbbbbb" },
    },
    create: (p) => {
        const mesh = new THREE.Mesh(
            new THREE.CylinderGeometry(0.2, 0.2, p.height, 16),
            new THREE.MeshStandardMaterial({ color: p.color })
        );
        mesh.position.y = p.height / 2;
        return mesh;
    },
});
```

Типы параметров: `number`, `color`, `colors` (список цветов), `boolean`, `string`, `select` (с `options`). `create` вызывается заново
при каждом изменении параметра и должен вернуть `THREE.Object3D`.

### Свои экранные эффекты

Каждый `defineEffect`, экспортированный из любого файла в `scripts/`, можно добавить в Look по имени.
Эффект с именем встроенного заменяет его.

```ts
import { defineEffect } from "white-engine";

export const scanlines = defineEffect({
    name: "scanlines",
    label: "Scanlines",
    params: {
        strength: { type: "number", default: 0.25, min: 0, max: 1, step: 0.05 },
    },
    shader: `
vec4 effect(vec2 uv, vec4 color) {
    float line = step(0.5, fract(uv.y * resolution.y / 2.0));
    return vec4(color.rgb * (1.0 - strength * line), color.a);
}`,
});
```

`shader` — код GLSL, который определяет `vec4 effect(vec2 uv, vec4 color)`: `uv` — место на экране
от 0 до 1, `color` — картинка в этой точке после предыдущих эффектов (линейный RGB). Каждый параметр —
uniform с тем же именем: `number` → `float`, `boolean` → `bool`, `color` → `vec3`, `select` → `int`
(номер варианта), `colors` → массив `vec3 имя[32]` и `int имяCount` (сколько цветов задано). Параметр нельзя называть `uv`, `color` и именами из таблицы ниже.

| В шейдере | Что это |
|---|---|
| `texel(uv)` | картинка в другой точке |
| `depthAt(uv)` | расстояние от камеры в метрах; нужно `inputs: ["depth"]` в определении |
| `normalAt(uv)` | направление поверхности относительно камеры; нужно `inputs: ["normal"]` |
| `positionAt(uv)` | где поверхность в этой точке экрана, в метрах от камеры (x вправо, y вверх, перед камерой z отрицательный — то же пространство, что у `normalAt`); нужно `inputs: ["depth"]` |
| `resolution` | размер картинки в пикселях (`vec2`) |
| `time` | секунды |
| `scroll` | на сколько пикселей картинки ушла камера с привязкой к пикселям (`vec2`): узор от `uv * resolution + scroll` остаётся на мире, а не на экране; без привязки — ноль |
| `toSRGB(c)`, `toLinear(c)` | перевод цвета между линейным и sRGB |

Ошибка в шейдере видна в Console редактора (и в консоли браузера у собранной игры) одной строкой: чей это код и
строка в нём — `Shader error in effect "scanlines", line 3: ...` (строки считаются от начала текста `shader`);
так же для поверхностей и неба. Команда `check` шейдеры не компилирует, а `render` — компилирует
и печатает ошибку.

### Свои поверхности

Каждый `defineSurface`, экспортированный из любого файла в `scripts/`, можно добавить в Look по имени
(список `surfaces`). Поверхность с именем встроенной заменяет её.

```ts
import { defineSurface } from "white-engine";

export const sway = defineSurface({
    name: "sway",
    label: "Sway",
    params: {
        amount: { type: "number", default: 0.02, min: 0, max: 0.2, step: 0.005 },
    },
    vertex: `
vec4 surfaceVertex(vec4 clip) {
    return clip + vec4(sin(time * 2.0 + clip.y) * amount * clip.w, 0.0, 0.0, 0.0);
}`,
});
```

| Поле | Что это |
|---|---|
| `vertex` | GLSL, определяет `vec4 surfaceVertex(vec4 clip)`: `clip` — место вершины на экране в clip-координатах (`clip.xy / clip.w` — от −1 до 1); вернуть новое |
| `fragment` | GLSL, определяет `vec3 surfaceColor(vec3 color, vec3 albedo)`: `color` — освещённый цвет пикселя (линейный RGB), `albedo` — цвет самого материала; вернуть новый цвет |
| `defines` | переключатели шейдеров three.js, например `["FLAT_SHADED"]` |

Все три поля необязательны. Параметры — uniform'ы с теми же именами, как у эффектов; ещё доступны
`resolution` (размер картинки в пикселях) и `time` (секунды), в `vertex` — атрибуты и матрицы three.js
(`position`, `normal`, `modelMatrix`, `viewMatrix`…). Поверхности одного стиля попадают в один шейдер:
вспомогательным функциям давайте свои имена. Поверхность действует на материалы проекта и на стандартные
материалы three.js в моделях из кода (`MeshStandardMaterial`, `MeshBasicMaterial` и подобные); свой
`ShaderMaterial` она не трогает. Тени от сдвинутых вершин не сдвигаются.

### Своё небо

Каждый `defineSky`, экспортированный из любого файла в `scripts/`, можно назвать небом сцены:
`"skyShader": "<имя>"` в `environment` (при `"sky": true`), параметры — в `skyParams`.

```ts
import { defineSky } from "white-engine";

export const dusk = defineSky({
    name: "dusk",
    label: "Dusk",
    params: {
        glowColor: { type: "color", default: "#ff8a3d" },
    },
    shader: `
vec3 sky(vec3 dir) {
    vec3 color = mix(skyHorizon, skyTop, sqrt(max(dir.y, 0.0)));
    // A band of warm light low over the horizon, on the side the sky is turned to
    float low = exp(-abs(dir.y) * 8.0) * max(-dir.z, 0.0);
    return color + glowColor * low;
}`,
});
```

`shader` — код GLSL, который определяет `vec3 sky(vec3 dir)`: `dir` — куда смотрят (вектор длины 1 в мире,
`y` вверх, «вперёд» — −Z), вернуть цвет в этом направлении (линейный RGB). Цвет ярче 1 — ярче белого: так
делают солнце, оно блестит в отражениях и попадает под эффект `glow`. Параметры — uniform'ы с теми же именами,
как у эффектов. Ещё доступны `skyTop`, `skyHorizon`, `skyGround` (три цвета неба из `environment` сцены — смена
дня и ночи через `self.setEnvironment` действует и на своё небо). Времени в шейдере неба нет: небо неподвижно
и перерисовывается только при смене параметров или этих цветов. Вспомогательным функциям давайте
свои имена. Небо рисуется на шесть граней куба вокруг сцены, по 1024 пикселя: деталь мельче десятой доли градуса
расплывётся. С `skyLight` оно же освещает сцену и отражается в металле. `skyImage`, если названа, важнее.

### Поведения

Каждый `defineBehavior`, экспортированный из любого файла в `scripts/`, можно повесить на объект компонентом
`script` (в редакторе — Add Component). Поведение запускается кнопкой Play.

```ts
import { defineBehavior } from "white-engine";

export const bob = defineBehavior({
    name: "bob",
    label: "Bob",
    params: {
        height: { type: "number", default: 0.3, min: 0, step: 0.05 },
        period: { type: "number", default: 2, min: 0.1, step: 0.1 },
    },
    // Один раз при запуске; то, что вернули, потом лежит в self.state
    start: (self) => ({ baseY: self.object.position.y }),
    // Каждый кадр, dt — секунды с прошлого кадра
    update: (self) => {
        const phase = (self.time / self.params.period) * Math.PI * 2;
        self.object.position.y = self.state.baseY + Math.sin(phase) * self.params.height;
    },
});
```

| Поле `self` | Что это |
|---|---|
| `object` | `THREE.Object3D` объекта, на котором висит поведение: его двигают, вращают, масштабируют |
| `params` | параметры из компонента (с подставленными значениями по умолчанию) |
| `state` | то, что вернул `start` |
| `root` | корень запущенной сцены, например `self.root.getObjectByName("Door")` |
| `registry` | материалы, модели и префабы проекта |
| `input` | клавиатура и мышь, см. ниже |
| `time` | секунды с момента запуска |
| `spawn(prefab, position?, parent?)` | создаёт в идущей игре экземпляр префаба и возвращает его `THREE.Object3D`; его поведения стартуют в этом же кадре |
| `destroy(object?)` | убирает объект со всем, что под ним (без аргумента — свой); исчезает в конце кадра |
| `move(x, y, z, step?)` | сдвигает объект (метры, по осям родителя; у объекта в корне сцены — мировым). Если у объекта есть сплошной `collider`, упирается в другие сплошные и скользит вдоль них; `false`, если что-то помешало. `step` — на уступ какой высоты (метры) объект, стоящий на опоре, заходит сам: ступенька, бордюр; по умолчанию 0 |
| `touching()` | объекты, чьих коллайдеров сейчас касается коллайдер этого объекта |
| `get(name, object?)` | другое поведение по имени — на своём объекте или на указанном: его `self` (с `params` и `state`) или `null` |
| `find(query)`, `findAll(query)` | активные объекты сцены, подходящие под запрос: `{ tag: "enemy" }`, `{ behavior: "drive" }`, `{ name: "Door" }` или несколько условий сразу. `find` — первый или `null` |
| `raycast(origin, direction, options?)` | луч по коллайдерам: ближайшее попадание `{ object, point, normal, distance }` или `null` (см. «Столкновения») |
| `screenRay(x?, y?)` | луч из камеры сцены через точку экрана (по умолчанию — где мышь): `{ origin, direction }` для `raycast`; `null`, если камеры нет |
| `fall(dt, gravity?)` | гравитация: вызывайте каждый кадр. Объект набирает скорость вниз (`gravity` — м/с², по умолчанию 20) и встаёт на сплошной коллайдер; `true`, пока стоит на опоре |
| `jump(speed)` | задаёт вертикальную скорость, с которой продолжит `fall`: `self.jump(7)` подбрасывает объект |
| `grounded()` | `true`, если объект стоит на сплошном коллайдере |
| `submerged(object?)` | на сколько метров объект под поверхностью воды (компонент `water` или река рельефа); 0 — не в воде |
| `flow(object?)` | куда несёт вода объект, `Vector3` в метрах в секунду: течение реки, в которой он; нулевой вне воды и в стоячей воде. `swim` плывёт по течению сам |
| `swim(dt, depth?, rise?)` | держит объект на плаву: в воде, где он на `depth` м (по умолчанию 1) или глубже под поверхностью, он всплывает до этой глубины (не быстрее `rise` м/с, по умолчанию 3) и не падает; `true`, пока на плаву. Вместо `fall`: `if (!self.swim(dt)) self.fall(dt)` |
| `playSound(name, options?)` | играет звуковой файл из `assets/`: `self.playSound("coin.wav")`; возвращает `{ stop(), volume, playing }` (см. «Звук») |
| `playMusic(name, options?)`, `stopMusic()` | музыка: играет по кругу и не останавливается при смене сцены (см. «Звук») |
| `tween(target, to, seconds, options?)` | плавно ведёт числа объекта `target` к значениям `to`: `self.tween(self.object.position, { y: 3 }, 0.5, { ease: "out" })` (см. «Картинка: движение, частицы, небо») |
| `after(seconds, fn)`, `every(seconds, fn)` | таймеры: вызвать функцию один раз через время или раз в интервал |
| `animation(object?)` | анимации своего объекта или указанного — клипы его модели из файла (`gltf`) и клипы из `defineClip`: `{ clips, playing, done, play(name, options?), stop() }` (см. «Анимация») |
| `animator(object?)` | компонент `animator` объекта: `{ state, time, get(param), set(param, value), trigger(param), go(state, fade?) }`; `null`, если компонента нет (см. «Анимация») |
| `particles(object?)` | компонент `particles` объекта: `emit(n)` — выбросить разом, `playing` — включить или выключить поток; `null`, если компонента нет |
| `environment`, `setEnvironment(change)` | окружение сцены (фон, небо, свет, туман, стиль) как сейчас и его смена на ходу: `self.setEnvironment({ ambientIntensity: 0.2 })` |
| `body(object?)` | физическое тело своего объекта или указанного: `{ velocity, setVelocity(x, y, z), push(x, y, z), setSpin(x, y, z) }`; `null`, если у объекта нет компонента `body` (см. «Физика») |
| `ui(object?)` | компоненты интерфейса своего объекта или указанного: `{ rect, text, image, button }` — поля компонентов, их можно менять; `null`, если у объекта нет `ui` (см. «Интерфейс игры») |
| `setText(text, object?)` | меняет текст компонента `text` |
| `sound(object?)` | компонент `sound` своего объекта или указанного: `{ play(), stop(), playing }`; `null`, если компонента нет |
| `loadScene(name)` | заменяет идущую сцену другой сценой проекта, когда закончится кадр: всё в этой уничтожается (поведения получают `destroy`), та стартует из своего файла |
| `overlay` | элемент страницы поверх картинки игры — для интерфейса на HTML и CSS (см. «Интерфейс игры») |
| `globals` | объект, который живёт от сцены к сцене, пока идёт игра: счёт, собранное. Общий для всех поведений: `self.globals.coins = 3` |

Ввод (`self.input`). Клавиши называются по `KeyboardEvent.code`: `"KeyW"`, `"Space"`, `"ArrowLeft"`,
`"ShiftLeft"`, `"Digit1"`. Кнопки мыши: 0 — левая, 1 — средняя, 2 — правая.

| Вызов | Что возвращает |
|---|---|
| `key(code)` | `true`, пока клавиша зажата |
| `keyPressed(code)` / `keyReleased(code)` | `true` только в том кадре, когда клавишу нажали / отпустили |
| `axis(minus, plus)` | `-1`, `0` или `1` по двум клавишам: `axis("KeyA", "KeyD")` |
| `mouseButton(n)`, `mousePressed(n)`, `mouseReleased(n)` | то же для кнопок мыши, по умолчанию левая |
| `mouseX`, `mouseY` | положение мыши на экране игры: от −1 до 1 слева направо и снизу вверх |
| `mouseDX`, `mouseDY` | сдвиг мыши с прошлого кадра в пикселях |
| `lockPointer()`, `unlockPointer()`, `pointerLocked` | захват мыши: курсор спрятан и не выходит из игры, мышь даёт только `mouseDX` / `mouseDY` — для обзора от первого лица. Браузер отдаёт курсор только по щелчку: захват случится при следующем нажатии на игру; Esc отпускает |
| `typed` | что набрано на клавиатуре с прошлого кадра, строкой: буквы как есть (с учётом раскладки и Shift), `"\\b"` — Backspace, `"\\n"` — Enter; зажатая клавиша повторяется |
| `wheel` | на сколько повернули колесо мыши с прошлого кадра; вниз — больше нуля |
| `touches` | пальцы на экране: список `{ id, x, y }`, координаты как у мыши |
| `pointers` | мышь и все пальцы: `{ id, x, y, down, pressed, released, touch }`; `id` 0 — мышь и первый палец |
| `stick("left")`, `stick("right")` | стик геймпада: `{ x, y }` от −1 до 1, `y` вверх; `{ 0, 0 }` в покое и без геймпада |
| `padConnected` | `true`, если геймпад подключён (браузер показывает его после первого нажатия кнопки на нём) |

Кнопки геймпада — те же клавиши с именами `"Pad0"`…`"Pad16"`: `key("Pad0")`, `keyPressed("Pad9")`. Номера по
обычной раскладке: 0 — A / крест, 1 — B / круг, 2 — X / квадрат, 3 — Y / треугольник, 4 и 5 — бамперы, 6 и 7 —
триггеры, 8 — back, 9 — start, 10 и 11 — нажатие стиков, 12–15 — крестовина вверх, вниз, влево, вправо.

На телефоне первый палец ведёт себя как мышь с зажатой левой кнопкой (`mouseX`, `mousePressed()`,
`screenRay()` работают как есть), остальные пальцы видны в `touches`. Экранные кнопки делают из элементов
интерфейса с `button`: пока кнопку держат (мышью или любым пальцем), `self.ui(кнопка)!.button!.held` равно
`true` — каждая кнопка под своим пальцем.

```ts
// Ходит от клавиш, от левого стика и от экранных кнопок Left / Right; прыгает по пробелу, кнопке A и кнопке Jump
update: (self, dt) => {
    const { input } = self;
    const held = (name: string) => self.ui(self.find({ name })!)?.button?.held ?? false;
    const x = input.axis("KeyA", "KeyD") + input.stick().x + Number(held("Right")) - Number(held("Left"));
    self.move(Math.max(-1, Math.min(1, x)) * self.params.speed * dt, 0, 0);
    if ((input.keyPressed("Space") || input.keyPressed("Pad0") || held("Jump")) && self.grounded()) self.jump(7);
    self.fall(dt);
},
```

```ts
update: (self, dt) => {
    self.object.position.x += self.input.axis("KeyA", "KeyD") * self.params.speed * dt;
    if (self.input.keyPressed("Space")) self.state.jumping = true;
},
```

В редакторе Play стартует в виде Game: камера сцены, ввод идёт поведениям. В виде Scene (камера редактора,
выбор и гизмо) клавиши и мышь управляют редактором и до поведений не доходят.

Объекты в игре появляются и исчезают через `self.spawn` и `self.destroy`. У поведения может быть третья
функция — `destroy(self)`: она вызывается, когда объект убирают или игра останавливается (если `start` уже был).
Поведения общаются через `state`: то, что вернул `start`, другое поведение получает как `self.get("имя", объект).state`.

```ts
// Каждые interval секунд создаёт префаб; сам считает, сколько создал
export const spawner = defineBehavior({
    name: "spawner",
    params: {
        prefab: { type: "asset", kind: "prefab", default: "" },
        interval: { type: "number", default: 1, min: 0.1 },
    },
    start: () => ({ next: 0, made: 0 }),
    update: (self) => {
        if (!self.params.prefab || self.time < self.state.next) return;
        self.state.next = self.time + self.params.interval;
        self.state.made++;
        const made = self.spawn(self.params.prefab, self.object.position.toArray());
        // Поведение lifetime на созданном объекте, если оно там есть
        const life = self.get<{ left: number }>("lifetime", made);
        if (life) life.params.seconds = 5;
    },
});

// Убирает свой объект через seconds секунд
export const lifetime = defineBehavior({
    name: "lifetime",
    params: { seconds: { type: "number", default: 3, min: 0 } },
    start: (self) => ({ born: self.time }),
    update: (self) => {
        if (self.time - self.state.born >= self.params.seconds) self.destroy();
    },
});
```

### Столкновения

Тело объекта для игры задаёт компонент `collider` (см. «Компоненты»): куб (`sizeX`, `sizeY`, `sizeZ`),
шар (`radius`) или капсула (`radius` и полная высота `height`). Значения по умолчанию совпадают с
одноимёнными формами `mesh`; всё задаётся в единицах объекта, то есть масштабируется вместе с ним.
`centerX` / `centerY` / `centerZ` сдвигают коллайдер от середины объекта.
Физики нет — ничего не падает и не отскакивает; коллайдеры дают две вещи:

- **Препятствия.** Двигайте объект через `self.move(x, y, z)`, а не меняя `position`: объект со сплошным
  коллайдером (`solid: true`) остановится у другого сплошного и проскользит вдоль него.
- **Триггеры.** У поведения могут быть функции `enter(self, other)` и `exit(self, other)`: они вызываются,
  когда коллайдер объекта начал и перестал касаться коллайдера другого объекта (`other` — его
  `THREE.Object3D`). Коллайдер с `solid: false` никого не останавливает и нужен только для этого: монета,
  зона у двери. Касание считается между любыми двумя коллайдерами, сплошными или нет.

```ts
// Монета: исчезает, когда её коснулся объект с поведением drive
export const pickup = defineBehavior({
    name: "pickup",
    enter: (self, other) => {
        if (self.get("drive", other)) self.destroy();
    },
});
```

Куб поворачивается вместе с объектом: плита, наклонённая на 20°, — пандус, стена под углом — стена под углом;
так его видят `self.move`, лучи, триггеры и физика. Шар и капсула не наклоняются: капсула всегда стоит
вертикально (у повёрнутого объекта тоже).
Длинный сдвиг `move` проходит шагами по 0.25 м, поэтому быстрый объект упирается и в тонкую стену; объект, который
двигают, меняя `position`, ни во что не упирается.

**Лучи.** `self.raycast(origin, direction, options?)` ищет ближайший коллайдер на пути луча. Начало и направление —
в координатах мира, `THREE.Vector3` или `[x, y, z]`. Возвращает `{ object, point, normal, distance }`: объект,
чей это коллайдер, точку и нормаль поверхности в ней, расстояние в метрах — или `null`.

| Опция | Что делает | По умолчанию |
|---|---|---|
| `distance` | как далеко достаёт луч, метры | без предела |
| `layers` | только коллайдеры этих слоёв: `["Wall", "Enemy"]` | все |
| `triggers` | `true` — попадать и в несплошные коллайдеры | `false` |
| `ignore` | объект, сквозь коллайдеры которого (и его детей) луч проходит; `null` — никого не пропускать | свой объект |

Коллайдер, внутри которого луч начинается, не считается.

```ts
// Выстрел туда, где мышь: убирает первого врага на пути
update: (self) => {
    if (!self.input.mousePressed()) return;
    const ray = self.screenRay();
    const hit = ray && self.raycast(ray.origin, ray.direction, { distance: 50 });
    if (hit && hit.object.userData.tag === "enemy") self.destroy(hit.object);
},
```

**Гравитация.** Физики тел нет, но объект с коллайдером может падать и прыгать: `self.fall(dt)` каждый кадр,
`self.jump(скорость)` для прыжка, `self.grounded()` — стоит ли он на опоре. Объект, который стоит на
движущемся коллайдере (лифт или платформа, которую двигает твин или другое поведение), едет вместе с ним.

```ts
// Ходит, падает и прыгает; объекту нужен сплошной collider
export const walker = defineBehavior({
    name: "walker",
    params: { speed: { type: "number", default: 4 }, jump: { type: "number", default: 7 } },
    update: (self, dt) => {
        const { input, params } = self;
        // Последнее число — высота ступеньки, на которую он заходит без прыжка
        self.move(input.axis("KeyA", "KeyD") * params.speed * dt, 0, input.axis("KeyW", "KeyS") * params.speed * dt, 0.3);
        if (input.keyPressed("Space") && self.grounded()) self.jump(params.jump);
        self.fall(dt);
    },
});
```

Лестница — это коллайдеры-кубы ступеньками: на уступ не выше `step` объект заходит сам и так же сам сходит с
него (с уступа выше `step` — падает). В прыжке на уступ он не заходит — только с опоры.

**Склоны.** Пандус — куб, наклонённый поворотом объекта (`"rotation": [0, 0, 20]`). Объект, который ходит через
`self.move` со `step` больше нуля, поднимается по нему и спускается, не отрываясь от земли; скорость вдоль
земли та же, что на ровном. Склон круче примерно 50° — стена. Без `step` (ноль) склон — тоже стена: по нему
ходят тем же механизмом, что и по ступенькам. С крутого склона объект сам не съезжает. Земля компонента
`terrain` — тоже склоны: по ней ходят так же (см. «Рельеф»).

```json
{ "name": "Ramp", "position": [0, 0.75, 0], "rotation": [0, 0, 20], "scale": [5, 0.2, 3], "components": [{ "type": "mesh" }, { "type": "collider" }] }
```

**Теги.** Поле `tag` объекта — любое слово. В игре оно лежит в `object.userData.tag`; объекты с тегом находит
`self.findAll({ tag })`.

**Сцены.** Игра состоит из сцен проекта, идёт всегда одна. Переход — `self.loadScene`; то, что должно его
пережить, кладут в `self.globals`.

```ts
// Дверь: когда её коснулся игрок, игра переходит в другую сцену
export const door = defineBehavior({
    name: "door",
    params: { to: { type: "asset", kind: "scene", default: "" } },
    enter: (self, other) => {
        if (other.userData.tag !== "player" || !self.params.to) return;
        self.globals.doors = ((self.globals.doors as number) ?? 0) + 1;
        self.loadScene(self.params.to);
    },
});
```

В редакторе Play после перехода идёт в той сцене (читает её файл с диска), а Hierarchy и Inspector
по-прежнему показывают открытую сцену.

### Картинка: движение, частицы, небо

**Твины и таймеры.** `self.tween(target, to, seconds, options?)` каждый кадр понемногу ведёт числа `target` к
значениям из `to`. `target` — что угодно с числами: `self.object.position`, `.scale`, `.rotation`, поля
из `self.ui()`. Опции: `ease` — `"linear"` (по умолчанию), `"in"` (разгон), `"out"` (торможение), `"inOut"`;
`loop` — `"repeat"` (сначала) или `"yoyo"` (туда и обратно), оба без конца; `delay` — секунды до старта;
`done` — функция по приходу. `self.after(seconds, fn)` вызывает функцию один раз, `self.every(seconds, fn)` —
раз в интервал. Все три возвращают `{ stop(), running }` и кончаются вместе с объектом поведения; пока объект
выключен, они ждут.

```ts
// Дверь уезжает вверх за полсекунды, через 3 секунды возвращается
enter: (self) => {
    const y = self.object.position.y;
    self.tween(self.object.position, { y: y + 3 }, 0.5, { ease: "out" });
    self.after(3, () => self.tween(self.object.position, { y }, 0.5, { ease: "in" }));
},
```

**Частицы** — компонент `particles` (поля — в «Компонентах»): искры, дым, пыль, брызги. Вылетают вдоль
локальной оси Y объекта в пределах `spread` градусов (0 — струя, 180 — во все стороны), живут `lifetime`
секунд, меняют размер (`size` → `sizeEnd`, метры) и цвет (`color` → `colorEnd`); `gravity` тянет вниз, а
отрицательная поднимает, как дым. Они остаются в мире: движущийся источник оставляет след. `additive` —
светящиеся (огонь, искры), иначе непрозрачные (дым, пыль). `shape`: `square` — жёсткие квадраты под
пиксель-арт, `circle`, `soft`. `rate` — поток в секунду при `playing`; разовый выброс — из поведения:
`self.particles()?.emit(30)`. На частицы не действуют свет, туман и тени; в редакторе они движутся и при правке сцены.

**Спрайт и текст в мире.** `sprite` — плоская картинка из `assets/` размером `width` × `height` метров, без
освещения; `label` — строка текста высотой `size` метров (`\n` — перенос, `outline` — обводка в долях высоты
строки). С `billboard` (по умолчанию) оба всегда повёрнуты к камере. Текст меняют из поведения так же, как в
интерфейсе: `self.setText("-25", object)`. Это не интерфейс: у них есть место в сцене, их заслоняют объекты.

**Небо** — в `environment` сцены: `"sky": true` заменяет ровный фон градиентом из `skyTop` (зенит),
`skyHorizon` и `skyGround` (ниже горизонта). Небо привязано к миру: камера поворачивается — оно тоже.
`skyImage` — картинка-панорама из `assets/` вместо трёх цветов: вдвое шире, чем выше (equirectangular), не уже
64 пикселей, лучше от 1024. `skyShader` — небо, нарисованное кодом (`defineSky` в `scripts/`, см. «Своё небо»):
солнце, облака, звёзды; его параметры — в `skyParams`. В общем проекте есть `sun` (солнце, ореол, облака поверх
трёх цветов сцены) и `stars`. `skyRotation` поворачивает любое небо вокруг вертикали, градусы: при 0 солнце
неба `sun` стоит впереди (по −Z), положительный угол уводит его влево.

```json
{ "sky": true, "skyShader": "sun", "skyRotation": 30, "skyParams": { "sunHeight": 25, "clouds": 0.35 }, "skyLight": 1 }
```

**Свет неба** — `skyLight` в `environment` больше 0: небо (без неба — ровный `background`) освещает сцену со всех
сторон и отражается в гладких и металлических материалах (`roughness` ближе к 0, `metalness` ближе к 1). Без
него металл без прямого света чёрный. Это свет вдобавок к `ambientIntensity`: включив, убавьте тот.

```json
{ "sky": true, "skyLight": 1, "ambientIntensity": 0.3 }
```

**Свечение** — свойство материала: поле `glow` больше 0 разливает свет материала (`emissive` ×
`emissiveIntensity` × `glow`) на соседние пиксели. Работает в любом стиле и без стиля; то, что стоит перед
светящимся объектом, его свет заслоняет. `glowRadius` — как далеко свет разливается, в процентах высоты
картинки (3 — небольшой ореол лампы, 10–15 — широкое зарево); в одном кадре — не больше четырёх разных радиусов:

```json
{ "color": "#3a2a1a", "emissive": "#ffb347", "emissiveIntensity": 3, "glow": 1 }
```

Отдельно есть эффект `glow` в Look (поля — во «Встроенных эффектах») — он про всю картинку, а не про материал:
всё, что ярче `threshold` (сильный свет, небо в окне), разливает свет вокруг себя:

```json
{ "effects": [{ "effect": "glow", "threshold": 0.9, "strength": 1.2, "radius": 14 }] }
```

**Мягкий свет** — три вещи, которые делают сцену из простых форм объёмной; все три собраны в общем стиле `Soft`.
Эффект `ao` (затенение в углах): темнеет там, где поверхности сходятся, — под ящиком на полу, в углу комнаты;
`radius` — как далеко поверхность затеняет соседнюю (метры), `strength`, `tint` — цвет тени. Поле света
`shadowSoftness`: 0 — жёсткий край тени, 1 — обычный, 3–5 — мягкий. `toneMapping: "aces"` в стиле сжимает яркое,
как плёнка, — свет можно делать сильнее, и картинка не выгорает. Эффект `smooth` сглаживает «лесенку» на краях:
ставьте его в стиль полного размера (`pixelSize` 1), где есть `ao` или `outline`, после них; в пиксель-арте он не нужен.

```json
{ "toneMapping": "aces", "exposure": 1.1, "effects": [{ "effect": "ao", "radius": 0.5, "strength": 1.2 }] }
```

**Зоны** — компонент `zone`: коробка (`sizeX` × `sizeY` × `sizeZ` в единицах объекта, поворачивается и
масштабируется вместе с ним) со своим окружением. Пока камера сцены внутри, действуют её `background`,
`ambientColor`, `ambientIntensity`, `fog`, `fogColor`, `fogNear`, `fogFar` и `look` (пустой `look` оставляет стиль
сцены); цвета и числа переходят за `blend` секунд. Так делают воду, пещеру, комнату. `"sky": false` у зоны убирает небо сцены, пока камера внутри: вместо него ровный
`background` зоны (в пещере над головой не облака); само небо зона не меняет.
В редакторе при правке сцены зона включается, когда в неё влетает камера редактора.

**День и ночь, погода** — из поведения через `self.setEnvironment(change)`: меняет названные поля окружения,
остальные не трогает; `self.environment` — как оно сейчас.

```ts
// На объекте солнца: темнеет небо и общий свет по мере того, как солнце садится
update: (self) => {
    const height = Math.max(0, Math.sin((self.time / 60) * Math.PI * 2));
    self.setEnvironment({ ambientIntensity: 0.15 + 0.85 * height, skyTop: height > 0.2 ? "#2f6fc4" : "#05070f" });
},
```

Не выключайте объект своего поведения (`self.object.visible = false`), чтобы «спрятать» его: поведения
выключенного объекта перестают работать, и включить его обратно будет некому.

**Рельеф материала** — поля материала `normalMap` (карта нормалей: голубоватая картинка «куда смотрит
поверхность»), `normalScale` (глубина рельефа) и `roughnessMap` (где шершаво — светлое, где блестит — тёмное;
умножается на `roughness`). Картинки из `assets/`, повторяются и сглаживаются так же, как `texture`.

### Модели из файлов (glTF)

Модель, сделанная в Blender или взятая готовой, — файл `.glb` в `assets/` (или `.gltf` вместе с его `.bin` и
картинками рядом). В сцене это компонент `gltf` (поля — в «Компонентах»): файл называется с расширением.

```json
{ "name": "Robot", "position": [0, 0, 0], "components": [{ "type": "gltf", "file": "robot.glb", "animation": "Walk" }] }
```

Модель приходит со своими материалами и размером — как сделана, так и стоит; подогнать — `scale` объекта.
Стили (контур, toon, пиксели) на неё действуют, как на всё остальное. Коллайдера у неё нет: добавьте
`collider` на тот же объект (в редакторе новый коллайдер сам встаёт коробкой вокруг модели, кнопка Fit в его
заголовке делает это заново). `animation` — имя клипа из файла, который играет с начала игры (`loop`, `speed`);
в редакторе он играет и при правке сцены, а Inspector предлагает клипы файла списком. Из поведения:

```ts
// Идёт — играет Walk, стоит — Idle; смена за 0.2 секунды
update: (self) => {
    const model = self.animation();
    const clip = self.input.axis("KeyA", "KeyD") !== 0 ? "Walk" : "Idle";
    if (model.playing !== clip) model.play(clip, { fade: 0.2 });
},
```

`self.animation(object?)` даёт `{ clips, playing, done, play(name, { loop, speed, fade }), stop() }`; `clips` —
имена клипов файла (пусто, пока файл грузится) и клипов из скриптов, `play` возвращает `false`, если такого клипа
нет. `check` сообщит о файле, которого нет в `assets/`, но внутрь файла не заглядывает: имя клипа
проверяет только запуск (`render` напечатает предупреждение). Файлы моделей у каждого проекта свои.
Когда клипов несколько и они сменяют друг друга по правилам (стоит, идёт, прыгает) — берите аниматор, см. ниже.

### Анимация: клипы и аниматор

**Клип** — ключи во времени для места, поворота, размера и включённости объекта и того, что под ним. Каждый
`defineClip`, экспортированный из любого файла в `scripts/`, можно играть на любом объекте.

```ts
import { defineClip } from "white-engine";

export const open = defineClip({
    name: "Open",
    // Считать от того, как объект стоит: тот же клип откроет любую дверь
    relative: true,
    tracks: [
        { property: "rotation.y", keys: [{ time: 0, value: 0 }, { time: 1, value: 90, ease: "out" }] },
        // Другой объект — путём из имён от того, на котором клип играет
        { object: "Handle", property: "position", keys: [{ time: 0, value: [0, 1, 0] }, { time: 0.2, value: [0, 0.95, 0] }] },
    ],
});
```

| Поле клипа | Что это |
|---|---|
| `name` | имя, по нему клип называют в сцене и в коде |
| `tracks` | дорожки: каждая ведёт одно свойство одного объекта |
| `length` | длина в секундах; без неё клип кончается на последнем ключе |
| `relative` | `true` — значения прибавляются к тому, как объект стоял, когда клип начался (место, поворот, размер); иначе это сами значения, как в файле сцены |

| Поле дорожки | Что это |
|---|---|
| `object` | кого двигать: путь из имён от объекта, на котором играет клип (`"Arm/Hand"`); без него — сам объект. Имя ищется среди детей, а если там нет — глубже: так `"Head"` достаёт часть модели из файла |
| `property` | `"position"`, `"rotation"` (градусы), `"scale"` — значение `[x, y, z]` (у `scale` можно одно число); `"position.x"`, `"rotation.y"`, `"scale.z"` и так далее — одна ось, значение — число; `"active"` — `true` / `false` |
| `keys` | ключи `{ time, value, ease? }`: `time` — секунды от начала клипа; `ease` — как значение приходит сюда от прошлого ключа: `"linear"` (по умолчанию), `"in"`, `"out"`, `"inOut"` или `"step"` (стоит и в этот момент прыгает) |

Дорожка одной оси (`"position.y"`) остальные оси не трогает — их может двигать поведение. Поворот идёт по
числам, а не кратчайшим путём: от 0 до 360 — полный оборот.

Играет клип компонент `animation` (поля — в «Компонентах»): `clip` — имя, `autoplay`, `loop` — `"repeat"` (сначала),
`"once"` (остаётся в последней позе) или `"yoyo"` (туда и обратно), `speed`.

```json
{ "name": "Door", "components": [{ "type": "animation", "clip": "Open", "loop": "once", "autoplay": false }] }
```

Из поведения — `self.animation(object?)`: `play(name, { loop, speed, fade })` запускает клип по имени (клип
модели из файла, если у неё есть такой, иначе клип из скриптов), `stop()` останавливает — то, что клип двигал,
возвращается туда, где было до него; `playing` — имя идущего клипа, `done` — клип `once` доиграл до конца.

```ts
// Дверь открывается, когда к ней подошёл игрок
enter: (self, other) => {
    if (other.userData.tag === "player") self.animation().play("Open", { loop: "once" });
},
```

Клип двигает объект напрямую, как `position` в коде: в стены он не упирается. Платформа, которую двигает
клип, возит на себе того, кто стоит на ней через `self.fall`. Клипы играют только в игре (в редакторе при
правке сцены объекты стоят, как записаны в файле).

**Аниматор** — состояния объекта, у каждого свой клип, и правила перехода между ними. Каждый
`defineAnimator` из `scripts/` вешается компонентом `animator`.

```ts
import { defineAnimator } from "white-engine";

export const hero = defineAnimator({
    name: "hero",
    params: {
        speed: { type: "number", default: 0 },
        jump: { type: "boolean", default: false },
    },
    start: "Idle",
    states: {
        Idle: { clip: "Idle" },
        Walk: { clip: "Walk", speed: 1.5 },
        Jump: { clip: "Jump", loop: "once" },
    },
    transitions: [
        // Без from — из любого состояния
        { to: "Jump", when: (p) => p.jump, fade: 0.1 },
        // after: "end" — когда клип состояния доиграл; число — через столько секунд в состоянии
        { from: "Jump", to: "Idle", after: "end", fade: 0.2 },
        { from: "Idle", to: "Walk", when: (p) => p.speed > 0.1, fade: 0.2 },
        { from: "Walk", to: "Idle", when: (p) => p.speed <= 0.1, fade: 0.2 },
    ],
});
```

Клип состояния — клип модели из файла на том же объекте или клип из `defineClip`; `loop` и `speed` — как у
`play`. Переходы проверяются каждый кадр по порядку, срабатывает первый подходящий: `from` — состояние, список
состояний или ничего (любое), `when(params, time)` — условие (`time` — секунды в состоянии), `after`, `fade` —
за сколько секунд клипы перетекают друг в друга. Поведение только ставит параметры:

```ts
update: (self, dt) => {
    const animator = self.animator();
    const x = self.input.axis("KeyA", "KeyD");
    self.move(x * 4 * dt, 0, 0);
    animator?.set("speed", Math.abs(x) * 4);
    // trigger: параметр равен true до первого же перехода, потом снова false — для разового: прыжок, удар
    if (self.input.keyPressed("Space")) animator?.trigger("jump");
},
```

`self.animator(object?)` — `{ state, time, get(param), set(param, value), trigger(param), go(state, fade?) }`;
`go` ставит состояние сразу, мимо правил. `check` проверяет клипы и аниматоры сами по себе (неизвестное
свойство дорожки, значение не того вида, переход в состояние, которого нет) и компоненты сцены (нет такого
клипа или аниматора, лишний параметр); есть ли у модели клип, названный в состоянии, покажет только запуск.

### Физика

Настоящая физика (библиотека cannon-es): тела падают, катятся, толкают друг друга и отскакивают. Объект
становится телом, когда у него есть компонент `body` (как Rigidbody в Unity) и сплошной `collider` — его
форма; поля — в «Компонентах».

```json
{
  "name": "Crate",
  "position": [0, 3, 0],
  "components": [{ "type": "mesh" }, { "type": "collider" }, { "type": "body", "mass": 2, "bounce": 0.3 }]
}
```

- **Тело** (`body` + `collider`) двигает физика: `position` и `rotation` в файле — только начало.
- **Всё остальное со сплошным `collider`** — то, во что тела упираются: пол, стены, платформы, игрок. В физике
  такой объект стоит там, где стоит в сцене, с его настоящим поворотом — наклонная плита работает как пандус
  для тел. Если его двигает поведение (`self.move`, смена `position`), он расталкивает тела на пути.
- **Триггеры** (`solid: false`) в физике не участвуют, `enter` / `exit` работают как раньше.

`mass` — килограммы: тяжёлое тело сдвигает лёгкое. `friction`: 0 — лёд, 1 — цепко. `bounce`: 0 — падает
намертво, 1 — отскакивает на ту же высоту. `damping` — как быстро тело само теряет скорость и вращение.
`lockRotation` не даёт телу опрокидываться, `gravity: false` — оно висит, пока его не толкнут. Сила тяжести
— `gravity` в `project.json`. Слои столкновений (`collider.layer`, `noCollision`) действуют и на физику.

Из поведения тело получают через `self.body(object?)`:

```ts
// Пинает тело, которого коснулся, в ту сторону, куда оно от объекта
enter: (self, other) => {
    const body = self.body(other);
    if (!body) return;
    const away = other.position.clone().sub(self.object.position).setY(0).normalize();
    body.push(away.x * 6, 4, away.z * 6);
},
```

`push` — толчок (меняет скорость на столько, делённое на массу), `setVelocity` задаёт скорость, `velocity` её
читает, `setSpin` задаёт вращение. Поставить тело в другое место — просто изменить `self.object.position`.

Персонаж, который ходит через `self.move` и `self.fall`, — не тело (компонент `body` ему не нужен): на тело
он может встать, а вбок входит в него и расталкивает. Проверить физику без редактора:
`npm run render -- sample сцена --time 2 --state` печатает, куда всё прикатилось.

Ограничения: тело, зажатое между игроком и стеной,
игрок проходит насквозь; очень быстрое маленькое тело может пролететь сквозь тонкую стену.

### Интерфейс игры

Счёт, полоска жизни, меню — плоские элементы поверх картинки. Как в Unity, интерфейс живёт внутри Canvas:
это объект с компонентом `canvas`, он и есть экран; его поле `height` — сколько единиц интерфейса экран в высоту. Элемент — объект под ним с компонентом
`ui` (его место на экране) и любыми из `text`, `image`, `button` на нём же; поля — в «Компонентах».
Элемент вне Canvas не рисуется (`check` об этом сообщит). Canvas'ов в сцене может быть несколько (HUD, меню
паузы): `active: false` у Canvas прячет всё, что в нём. `position`, `rotation` и `scale` Canvas и элементов
на интерфейс не влияют.

```json
{
  "name": "HUD",
  "components": [{ "type": "canvas", "height": 540 }],
  "children": [
    {
      "name": "Score",
      "components": [
        { "type": "ui", "anchor": "top-left", "x": 16, "y": 12, "width": 260, "height": 40 },
        { "type": "text", "text": "Score: 0", "size": 30, "align": "left", "outline": 2 }
      ]
    },
    {
      "name": "Play",
      "components": [
        { "type": "ui", "anchor": "bottom", "y": -20, "width": 160, "height": 44 },
        { "type": "image", "color": "#2d6cdf" },
        { "type": "text", "text": "Play" },
        { "type": "button" },
        { "type": "script", "script": "startGame" }
      ]
    }
  ]
}
```

**Место.** Для элементов Canvas экран всегда `height` единиц в высоту (поле `canvas`, по умолчанию 540; то же, что
Canvas Scaler в Unity), ширина — по форме
окна: 960 при 16:9. Все числа интерфейса — в этих единицах, поэтому он выглядит одинаково в окне любого размера.
`anchor` — к какой точке родителя элемент прикреплён (`top-left`, `top`, `top-right`, `left`, `center`,
`right`, `bottom-left`, `bottom`, `bottom-right`); той же своей точкой он туда и встаёт: `top-right` — правый
верхний угол элемента в правом верхнем углу родителя. `x`, `y` — сдвиг оттуда: `x` вправо, `y` вниз (отступ от
правого края — отрицательный `x`). Родитель — ближайший объект выше с компонентом `ui`, иначе сам Canvas, то есть весь экран;
дочерние элементы двигаются вместе с ним. `width` или `height`, равные 0, — «как у родителя»: так делают
контейнер или фон на весь экран. Меньше 0 — «как у родителя минус столько»: `"width": -40` у элемента с якорем
`center` оставляет по 20 единиц с каждой стороны.

**Раскладка.** `layout` на элементе ставит его дочерние элементы друг за другом: `direction` — `column` (сверху
вниз) или `row` (слева направо), `gap` — промежуток, `padding` — отступ от краёв, `align` — поперёк ряда:
`start`, `center`, `end` или `stretch` (на всю ширину колонки / высоту строки). У детей считаются только размеры:
их `anchor`, `x` и `y` не действуют. Сам контейнер под содержимое не растёт.

**Прокрутка.** `scroll` на элементе показывает только ту часть дочерних элементов, что внутри него; остальное
приезжает протягиванием (мышью или пальцем) и колесом мыши. `offset` — на сколько единиц содержимое ушло
вверх. Только по вертикали. Обычно вместе с `layout` на том же объекте — получается список.

**Что рисуется.** На одном объекте сначала `image`, поверх `text`. `image` без `texture` — прямоугольник цвета
`color`; с `texture` — картинка из `assets/`, растянутая на элемент и умноженная на `color`. `text`: `font` —
файл шрифта из `assets/` (ttf, otf, woff, woff2), без него шрифт системы; `wrap` переносит строки по ширине
элемента, `\n` в тексте — перенос; `outline` — обводка букв, чтобы текст читался на любой картинке; `sharp`
убирает сглаживание (для пиксельных шрифтов). Элементы рисуются в порядке объектов в сцене: тот, что ниже в
файле, — поверх. Скрыть элемент — `active: false` у объекта (в игре `object.visible = false`).

**Кнопка.** `button` делает элемент нажимаемым: поведения этого объекта получают `click(self)`, когда на нём
нажали и отпустили мышь (или палец). Под мышью кнопка светлеет, нажатая — темнеет; `"enabled": false`
выключает её. Кнопка сверху заслоняет те, что под ней.

**Слайдер.** `slider` — число от `min` до `max`, которое игрок ставит, нажав на элемент и ведя вдоль него
(`step` — шаг, 0 — любое значение). Рисуется сам: закрашенная цветом `fill` часть до значения и ползунок цвета
`knob`; фон — `image` на том же объекте. Поведения объекта получают `change(self, value)` при каждом изменении.

**Поле ввода.** `input` вместе с `text` на том же объекте: щелчок по элементу забирает клавиатуру, набранное
показывает `text` (его шрифт, размер и цвет), пока пусто — бледная подсказка `placeholder`; `max` — самая
длинная строка в символах. Поведения получают `change(self, text)` на каждую букву и `submit(self, text)` по
Enter. Щелчок мимо поля возвращает клавиатуру игре. Пока игрок печатает, клавиши по-прежнему видны и в
`self.input` (буква W двигает игрока) — если это мешает, не слушайте клавиши, пока
`self.ui(поле)!.input!.focused`.

```ts
// На объекте со slider или input: значение уходит в текст объекта Title
export const echo = defineBehavior({
    name: "echo",
    change: (self, value) => {
        const title = self.find({ name: "Title" });
        if (title) self.setText("Speed: " + value, title);
    },
    submit: (self, text) => console.log("entered", text),
});
```

```ts
// На объекте с button: каждый щелчок прибавляет очко и пишет счёт в текст объекта Score
export const clicker = defineBehavior({
    name: "clicker",
    start: () => ({ count: 0 }),
    click: (self) => {
        self.state.count++;
        const label = self.find({ name: "Score" });
        if (label) self.setText("Score: " + self.state.count, label);
    },
});
```

**Из поведений.** `self.setText(text, object?)` меняет текст. `self.ui(object?)` даёт поля всех компонентов
интерфейса объекта — `{ rect, text, image, button, layout, slider, input, scroll }`; их меняют напрямую (значение
слайдера — `slider.value`, набранное — `input.text`), результат виден в следующем кадре:

```ts
// Полоска жизни: ширина по числу от 0 до 1, красная, когда мало
const bar = self.ui(self.find({ name: "HealthBar" })!)!;
bar.rect.width = 200 * health;
bar.image!.color = health < 0.3 ? "#d33a3a" : "#3ad36b";
```

**HTML поверх игры.** `self.overlay` — элемент страницы точно поверх картинки игры (`null`, если страницы нет).
Это второй способ делать интерфейс — средствами браузера, а не компонентами: поведение кладёт туда свои
элементы и стили. Сам он пропускает мышь в игру; тому, что должно нажиматься, ставят `pointer-events: auto`.
Внутри него `var(--unit)` — длина одной единицы интерфейса (экран — 540 единиц в высоту), размеры через неё
держат свою долю картинки при любом окне. Вместе со сценой элемент убирается со всем содержимым. В картинку
команды `render` он не попадает, эффекты стиля и крупные пиксели на него не действуют.

```ts
start: (self) => {
    const hint = document.createElement("div");
    hint.textContent = "Press E";
    hint.style.cssText = "position: absolute; left: 50%; bottom: calc(var(--unit) * 40); font: calc(var(--unit) * 20) sans-serif; color: #fff;";
    self.overlay?.append(hint);
    return { hint };
},
destroy: (self) => self.state.hint.remove(),
```

То, что поведение изменило, живёт только в идущей игре, как и всё остальное. Щелчок по кнопке остаётся и
нажатием мыши для `self.input`.

Интерфейс рисуется поверх готовой картинки: эффекты стиля его не трогают, и при `pixelSize` больше 1 он
остаётся чётким. Если нужен интерфейс в тех же крупных пикселях — `pixelUi: true` в стиле; тогда берите
пиксельный шрифт с `sharp` и `height` у Canvas, равный высоте уменьшенной картинки, — единица интерфейса равна её пикселю.
Команда `render` рисует интерфейс вместе со сценой; `check` сообщит о `text`, `image` или `button` без `ui`
на том же объекте и о шрифте или картинке, которых нет в `assets/`.

### Звук

Звук — файл в `assets/` (mp3, ogg, wav), называется с расширением: `"coin.wav"`, с подпапкой —
`"music/theme.ogg"`. Новый файл достаточно положить в `assets/`. Играть его можно двумя способами.

**Компонент `sound`** (поля — в «Компонентах») — звук объекта: фон сцены, гул машины, костёр.

```json
{ "name": "Music", "components": [{ "type": "sound", "sound": "theme.ogg", "loop": true, "volume": 0.5 }] }
```

С `autoplay` (по умолчанию) он начинается вместе со сценой или когда объект появился; без него ждёт
`self.sound().play()`. Звук кончается вместе с объектом: когда тот убран (`self.destroy`) или выключен;
включённый снова, звук с `autoplay` начинается сначала. `spatial: true` — звук идёт из места объекта: чем
дальше от камеры сцены, тем тише, на расстоянии `range` метров не слышен совсем; слева от камеры он слышен в
левом ухе, справа — в правом. Если камера стоит далеко от того, что показывает (вид сверху, изометрия),
расстояние от неё мало что значит: повесьте на игрока компонент `listener` (полей у него нет) — тогда
расстояние считается от него, а лево и право остаются по камере.

**`self.playSound(name, options?)`** — звук из поведения: шаг, выстрел, подобранная монета. Он не привязан к
объекту поведения и доиграет, даже если объект в этом же кадре убрали.

| Опция | Что делает | По умолчанию |
|---|---|---|
| `volume` | громкость: 1 — как в файле, 0 — тишина | `1` |
| `pitch` | скорость: 2 — вдвое быстрее и на октаву выше | `1` |
| `loop` | играть по кругу, пока не остановят | `false` |
| `at` | откуда звук идёт: точка `[x, y, z]` / `THREE.Vector3` в мире или объект, за которым он следует | отовсюду |
| `range` | вместе с `at`: расстояние от камеры в метрах, на котором звук уже не слышен | `20` |

Возвращает `{ stop(), volume, playing }`: `volume` можно менять на ходу, `playing` становится `false`, когда
звук доиграл или остановлен.

```ts
// Монета: звенит и исчезает. Чуть разная высота, чтобы десять монет подряд не звучали одинаково
export const pickup = defineBehavior({
    name: "pickup",
    params: { sound: { type: "asset", kind: "sound", default: "" } },
    enter: (self, other) => {
        if (!self.get("drive", other)) return;
        if (self.params.sound) self.playSound(self.params.sound, { pitch: 0.9 + Math.random() * 0.2 });
        self.destroy();
    },
});
```

**Музыка** — единственный звук, который переживает смену сцены (`self.loadScene`); все остальные при
переходе останавливаются. Музыка одна: компонент `sound` с `"music": true` или
`self.playMusic(name, { volume, pitch, loop })` (по кругу, если не сказано `loop: false`). Если следующая сцена
называет музыкой тот же файл, он играет дальше без разрыва; другой файл занимает его место; сцена без музыки
оставляет ту, что играла. Музыка не кончается вместе с объектом, у неё нет места в мире, а у компонента она
всегда играет по кругу (`spatial` и `loop` не действуют); останавливает её `self.stopMusic()`.

```json
{ "name": "Music", "components": [{ "type": "sound", "sound": "theme.ogg", "music": true, "volume": 0.5 }] }
```

Браузер не даёт странице звучать,
пока человек её не тронул: в собранной игре то, что запущено раньше, начнётся с первым нажатием клавиши или
кнопки мыши. `check` сообщит о компоненте или параметре с именем файла, которого нет в `assets/`; команда
`render` звук не играет.

**Слои.** У коллайдера есть поле `layer` — имя слоя из `project.json` (в корне проекта); без него коллайдер
на слое `Default`. В `noCollision` перечислены пары слоёв, которые друг друга не замечают: их коллайдеры не
упираются друг в друга и не получают `enter` / `exit`. Все остальные пары сталкиваются.

```json
{
  "layers": ["Player", "Enemy", "Pickup"],
  "noCollision": [["Enemy", "Pickup"], ["Enemy", "Enemy"]]
}
```

`Default` в `layers` не пишут — он есть всегда, а в парах `noCollision` его называть можно. Пара из одного
слоя дважды — его коллайдеры не замечают друг друга. `check` сообщит о коллайдере со слоем, которого нет.

Параметр `{ type: "asset", kind: "object", default: "" }` — ссылка на объект той же сцены. В файле это имя
объекта (`"label": "Score"`), а поведение получает сам объект: `self.params.label` — `THREE.Object3D` или `null`,
если такого нет (искать через `self.find` не нужно). `check` сообщит об имени, которого в сцене нет; в редакторе
это список объектов сцены, на который объект можно перетащить из Hierarchy, а переименование объекта
обновляет ссылки на него. Берите его вместо параметра-строки с именем.

Параметр типа `asset` — ссылка по имени: `kind` — `"prefab"`, `"material"`, `"look"`, `"scene"` (сцена проекта, например та, куда ведёт дверь) , `"sound"` (звуковой файл из `assets/`), `"font"` (файл шрифта), `"texture"` (картинка) или `"layer"`; в Inspector это
список, `check` проверяет, что такой ассет есть. Созданные в игре объекты живут только в игре: в Hierarchy
редактора они показаны отдельным списком «Created in Play», после Stop их нет.

`start` и `update` можно не писать. Углы в three.js — в радианах (`THREE.MathUtils.degToRad`). Поведения
неактивных объектов (`active: false`) не запускаются. Если поведение бросило исключение, оно останавливается,
остальные продолжают работать; сообщение видно в строке статуса редактора.
Поведения работают на копии сцены: то, что они сделали с объектами в Play, после Stop исчезает.
Параметры поведения можно менять в Inspector прямо во время Play; при Stop редактор спросит, оставить ли правки.

## Как работать

- Расстановку объектов, свет и материалы меняйте в файлах `scenes/` и `materials/`; открытый редактор
  покажет результат сразу. Если в редакторе есть несохранённые правки той же сцены, он не станет
  перезагружать её сам, а сообщит об этом в строке статуса.
- Формы, которые проще вычислить, чем собрать из примитивов, описывайте кодом через `defineModel`.
- Землю с холмами и склонами делайте рельефом (`terrains/` и компонент `terrain`), а не плоскостью и кубами.
- Внешний вид игры целиком (пиксели, контуры, палитра, фильтры) задаётся стилем в `looks/`; свой фильтр —
  `defineEffect` в `scripts/`, своя добавка к материалам — `defineSurface`, своё небо — `defineSky`.
- Движение по ключам (дверь, лифт, кран) — `defineClip` и компонент `animation`; смена клипов по правилам
  (стоит, идёт, прыгает) — `defineAnimator` и компонент `animator`.
- Движение и логику объектов описывайте поведениями через `defineBehavior` и вешайте их компонентом `script`.
- После правок запускайте `npm run check -- sample`; чтобы увидеть результат — `npm run render -- sample`.
