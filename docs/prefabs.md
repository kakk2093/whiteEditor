# Префабы: как устроено

Экземпляры, переопределения, добавленное и убранное. Указатель — в `CLAUDE.md`.

- **Префаб** — `prefabs/<имя>.json` с `root`. Экземпляр в сцене — объект с полем `prefab` и своим
  transform; содержимое берётся из файла. Объекты внутри экземпляра не имеют `entityId`, поэтому клик
  во вьюпорте выбирает экземпляр целиком.
- **Переопределения** — поле `overrides` экземпляра: `{ "<путь из имён от корня префаба>": { active,
  position, rotation, scale, components: { "<ключ компонента>": { поля } } } }`, `"."` — корень.
  Ключ `name` даёт объекту префаба другое имя в этом экземпляре: пути и id по-прежнему идут по имени из
  префаба, новое имя ставится в самом конце (`renames` и `applyRenames` в `prefab.ts`; вложенный экземпляр
  разворачивается с `final = false`, чтобы имена ставил только внешний). `expandInstance` даёт
  экземпляр как обычный объект: содержимое префаба плюс переопределения; так его строит `createEntityObject`,
  так же его видят `Runtime` и валидация. Объекты внутри получают id `"<id экземпляра>/<путь>"` (на three.js-
  объекте — `userData.innerId`), по ним их знают `sceneStore.objects` и `Game.objects`, поэтому гизмо и
  правка в Play работают как с обычными. Путь, уходящий во вложенный экземпляр другого префаба, переносится
  в его собственные `overrides`. В редакторе: экземпляр в Hierarchy раскрывается (по умолчанию свёрнут), его
  внутренности — курсивом, изменённые — жирным; их можно выбрать и править в Inspector или гизмо. Методы
  store не пишут переопределения сами: `locate(id)` даёт копию объекта с применёнными переопределениями,
  метод правит её как обычный объект, `commit` сравнивает с префабом (`diffOverride`) и записывает разницу в
  экземпляр — вернул значение как в префабе, переопределение исчезло. Компоненты самого экземпляра
  (корня префаба) правятся так же (`locate(id, true)`). Revert — `revertOverrides(id)`. Unpack сохраняет
  переопределения в получившихся объектах. Изменённые поля в Inspector помечены (синяя жирная подпись,
  `sceneStore.overrideOf(id)`); правый щелчок по такой подписи — Revert to Prefab для одного поля
  (`revertOverrideField`). Apply (`applyOverrides(id)` в `actions.ts`, кнопки в Inspector и пункты
  контекстного меню) вписывает переопределения в префаб (`applyToPrefab`), сразу пишет файл префаба и
  убирает их из экземпляра: для экземпляра — все, для объекта внутри — только его. Во время Play и для
  префаба, открытого на редактирование, Apply недоступен. Режим редактирования префаба показывает его отдельной сценой, сцена
  ждёт в `stash`; выход сохраняет префаб.
- **Добавленное и убранное в экземпляре** — ещё четыре ключа той же записи `overrides["<путь>"]`:
  `addComponents` (список компонентов), `removeComponents` (список ключей), `addChildren` (список обычных
  объектов, пишутся целиком) и `removed: true` (объекта префаба в экземпляре нет). Всё применяет `applyAt` в
  `prefab.ts`: сначала `removed`, потом убранные и добавленные компоненты, правки полей, добавленные дети;
  для вложенного экземпляра другого префаба запись передаётся в его собственные `overrides` (`mergeOverride`).
  Компоненты идут прежним путём: метод store правит копию из `locate`, `diffOverride` сам находит, чего в
  префабе нет (`addComponents`) и что пропало (`removeComponents`). Объекты устроены иначе — **добавленный
  объект настоящий**: он лежит в `addChildren` экземпляра и правится напрямую, без `commit` (тот лишь не
  теряет `addChildren`). Его id не случайный, а выводится из места: `"<id того, в чём он лежит>/<имя>"`, и так
  же вниз по его детям — ровно те id, что ставит `expandInstance`, поэтому объекты three.js, `Game` и выделение
  находят его как раньше. Id назначает `assignAddedIds` (вызывается в `rebuild()`, выделение переезжает на
  новые id); объект, вынутый из экземпляра, получает обычный id. Поэтому `/` в id больше не значит «из
  префаба»: это решают `sceneStore.isInner(id)` (не настоящий объект, но лежит в экземпляре),
  `realEntity(id)`, `addedIn(id)`, `pathIn(id)`; модульный `findEntity` заходит и в `addChildren` и отдаёт
  `parentId` — id того, под чем объект лежит (у добавленного это не настоящий объект). Куда встанет новый
  объект, решает `slot(parentId)`: под экземпляром или под объектом префаба — в `addChildren` нужного пути.
  Правки, меняющие состав экземпляра (вставка, удаление, перенос, переименование добавленного, Revert),
  заканчиваются `restructure()` — уборка пустых записей и полная пересборка объектов сцены.
  `removeEntity` для объекта префаба пишет `removed` и стирает переопределения под ним; `restoreRemoved` и
  `restoreComponent` возвращают. В редакторе: под объектом префаба и под экземпляром можно создавать детей
  (меню, перетаскивание строки в Hierarchy, Ctrl+D на объекте префаба делает добавленную копию), Del и корзина
  убирают объект префаба из экземпляра; в Hierarchy добавленный помечен «+», убранный показан зачёркнутой
  строкой с кнопкой возврата; в Inspector у объектов экземпляра работают Add Component и крестик компонента,
  добавленный компонент выделен в заголовке, убранные перечислены с кнопкой Restore. Apply переносит всё это
  в файл префаба, Revert убирает. `check` проверяет новые ключи (нет такого компонента, компонент уже есть в
  префабе, совпадение имён, `removed` у корня).
