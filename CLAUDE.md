# whiteEditor

Редактор сцен для веб-игр на three.js в духе Unity. Личный инструмент и практика автора, не продукт.
Игра создаётся из одного места — из редактора; проект игры живёт в папке `projects/<имя>/`.

## Цели (в порядке важности)

1. **Модель Unity:** GameObject + компоненты, Hierarchy, Inspector с Add Component, окно Project с ассетами,
   префабы. Тяжёлые системы (физика, анимации, частицы, UI игры) — позже и в упрощённом виде.
2. **С инструментом должен хорошо работать ИИ-агент.** Весь проект — читаемые текстовые файлы (JSON, TS),
   которые можно писать руками; редактор подхватывает правки с диска; есть описание формата для агента
   и проверка без браузера. При конфликте с «красотой как в Unity» эта цель важнее.
3. **Просмотр рендера:** свет, туман, день/ночь, эффекты вроде погружения под воду должны быть видны
   прямо во вьюпорте — он рисует тем же three.js и тем же кодом движка, что и игра.

Разработку не привязываем к переносу конкретной игры. Прежняя игра автора (`D:\Projects\office`) —
только пример подхода «модели собраны функциями в коде».

## Как работать

- В чате — по-русски. Комментарии в коде — по-английски, в стиле окружающего кода (4 пробела, двойные
  кавычки, точки с запятой в `src/`; в `vite*.ts` и `tools/` — 2 пробела, одинарные кавычки, без `;`).
- После правок: `npx tsc -b`, `npx eslint .`, `npm run check -- demo`. Посмотреть, что получилось, без
  браузера: `npm run render -- demo [сцена]` и открыть PNG.
- Dev-сервер автор обычно держит запущенным сам на `http://localhost:5173` — второй не поднимать,
  а открыть этот адрес в браузере.
- Перетаскивание (HTML5 drag-and-drop) инструмент браузера настоящей мышью не воспроизводит — проверять
  программными событиями и честно говорить, что мышью не проверено.
- Автор часто держит редактор открытым в своём браузере на том же сервере и работает в нём одновременно:
  файлы в `projects/demo/`, которых ты не создавал (`folders.json`, `project.json`, сцены), могут быть его —
  не удалять и не перезаписывать, не посмотрев. Для проверок, которые пишут в проект, брать данные только в
  памяти страницы (`sceneStore.update({ folders })`, `registry.setPrefab(...)`) или временные файлы со своим
  именем (`scenes/_t.json`) и убирать их за собой. Вызов `reveal` открывает окно проводника на его рабочем столе.
- Спрашивать, продолжать ли, не нужно: автор просит идти по списку до конца и останавливаться только там, где
  он сам назвал точку остановки, или где решение действительно его (формат файла, раскладка интерфейса).
- Патчи на несколько файлов писать скриптом в scratchpad и запускать `node <файл>`: `node -e "..."` в Git Bash
  ломается на обратных кавычках и `${...}`.
- Коммитить только по просьбе.

## Команды

```bash
npm run dev              # редактор
npm run check -- demo    # проверка проекта: сцены, префабы, материалы, типы скриптов (без браузера)
npm run build:game -- demo [сцена]   # сборка игры в projects/demo/build (index.html + game.js)
npm run render -- demo [сцена]       # картинка сцены в projects/demo/renders/<сцена>.png (без редактора)
npx tsc -b               # типы редактора
npx eslint .
```

## Как устроено

- **Проект** — папка `projects/<имя>/`: `scenes/`, `materials/`, `prefabs/`, `looks/` (JSON), `scripts/` (TS), `assets/`,
  плюс `tsconfig.json`, `AGENTS.md` (генерируется, перезаписывается при запуске сервера) и `CLAUDE.md`
  (создаётся один раз, для заметок автора). Проекты лежат только внутри папки редактора: так у скриптов
  и редактора одна копия three.js.
- **Формат** (версия 3) подробно описан в `projects/demo/AGENTS.md`. Кратко: сцена — дерево объектов;
  объект — контейнер с `position`, `rotation` (градусы), `scale`, `components`, `children`; значения
  по умолчанию и `id` можно не писать. Компоненты: `mesh`, `light`, `camera`, `collider`, `body`, `sound`, `listener`, `canvas`, `ui`, `text`, `image`, `button`, `model`,
  `script`; не больше
  одного каждого типа, кроме `script` (сколько угодно, но каждое поведение один раз). Настройки сцены —
  `environment` (фон, окружающий свет, туман).
- **Компоненты описаны в `src/engine/components.ts`** (`componentDefs`): поля, функция сборки и особенности.
  Inspector, валидация и `AGENTS.md` строятся из этих определений — новый компонент добавляется там.
- **Поле, нужное не всегда:** у `ParamDef` есть необязательное `when` — `{ kind: ["spot"] }`: поле имеет смысл,
  только пока другие поля того же объекта имеют одно из этих значений. Inspector такие поля прячет
  (`fieldApplies`), `AGENTS.md` пишет условие в таблице; значение в файле хранится в любом случае. Так
  размечены `range`, `angle` и `shadowSize` у света.
- **Материал** — ассет `materials/<имя>.json`; `mesh.material` ссылается по имени. Один three.js-материал
  на ассет, общий для всех мешей (`userData.shared`, при удалении меша не освобождается).
- **Текстура** — поле `texture` материала: имя файла картинки из `assets/` проекта (`"tiles.png"`), плюс
  `tilingX` / `tilingY` и `filter` (`nearest` по умолчанию — чёткие пиксели). Это параметр типа
  `asset` с `kind: "texture"`; список картинок `Registry` получает через `setTextures(base, files)`:
  редактор — из `GET /__api/projects/<имя>/assets` и адреса `/projects/<имя>/assets/`, собранная игра —
  `./assets/`, `check` — только имена для проверки. Картинка грузится один раз на файл
  (`Registry.loadImage`), карта создаётся на материал; пока картинка в пути, материал рисуется одним
  цветом. `renderStill` ждать не может, поэтому `render` сначала вызывает `registry.preloadTextures()`.
  Новая или изменённая картинка в `assets/` перезагружает проект в редакторе (тем же событием, что и скрипт).
  `check` теперь проверяет и поля материалов (`validateMaterial`).
- **Интерфейс игры** (`src/engine/ui.ts`) — плоские элементы поверх картинки внутри Canvas, как в Unity: Canvas
  — объект с компонентом `canvas` (без полей, метка `userData.uiCanvas`), он и есть экран; вне Canvas элементы
  не рисуются (`UiLayer.layout` начинает считать их только под ним), `check` о таких сообщает (в префабе — нет:
  где встанет экземпляр, неизвестно). Новый Text / Image / Button из меню создания встаёт в Canvas сам
  (`canvasFor` в `createMenu.ts`: в тот, где выбранный объект, иначе в первый, иначе Canvas создаётся).
  Элемент — объект под Canvas с компонентом `ui` (место: `anchor` из девяти точек, `x`, `y`,
  `width`, `height`; 0 — «как у родителя») и любыми из `text`, `image`, `button` на нём же. Компоненты ничего
  не рисуют в three.js: каждый кладёт в объект метку с полями (`userData.ui`, `uiText`, `uiImage`, `uiButton`),
  `uiOf(object)` их собирает. Единицы — не пиксели: для элементов Canvas экран всегда `height` единиц в высоту (поле компонента `canvas`,
  по умолчанию 540), ширина по форме окна; родитель элемента — ближайший объект выше с `ui`, иначе Canvas (экран).
  **Рисование:** `UiLayer.draw(width, height)` раскладывает элементы и красит их на 2D-канвасе браузера
  (`fillText`, `drawImage`), канвас — текстура (`CanvasTexture`), которую `RenderPipeline.render(scene, camera,
  dt, ui)` кладёт поверх готового кадра отдельным проходом (`drawUi`, шейдер `OVERLAY`) — после эффектов Look,
  в обеих ветках (с Look и без). Размер канваса — область вывода, делённая на `pixelSize` (поле Look `pixelUi`,
  по умолчанию включено), так что в пиксель-арте интерфейс в тех же крупных пикселях. Перекрашивается только
  когда изменилась «подпись» (JSON из мест, полей, состояния кнопок, загруженности картинок и шрифтов).
  Тонирование картинки, осветление кнопки под мышью и `sharp`-текст (порог прозрачности через
  `getImageData`) делаются на двух запасных канвасах. **Кнопки:** `Game.update` до поведений зовёт
  `ui.update(aspect, input)` — раскладка в единицах зависит только от формы картинки (`Game.resize`), поэтому
  щелчки не зависят от того, рисовался ли кадр; нажал и отпустил на одной кнопке — `Runtime.click(object)` —
  хук `click(self)` у поведений объекта. **Из поведений:** `self.ui(object?)` — те самые объекты полей
  (`{ rect, text, image, button }`), их правят напрямую; `self.setText`. Поля — копии, сделанные при сборке
  объекта, данные сцены не трогают. **Шрифты** — файлы `assets/` (ttf, otf, woff, woff2), параметр `asset` с
  `kind: "font"`, `registry.setFonts`, `registry.fontFamily(name)` (через `FontFace`, `null`, пока не загружен);
  `registry.getImage(name)` — картинка, если загружена; `preloadTextures` теперь грузит все картинки и шрифты
  проекта (для `render`). **Редактор:** раздел UI в меню создания (Text, Image, Button — готовые наборы
  компонентов), Add Component для `text` / `image` / `button` сам добавляет `ui`; вьюпорт рисует интерфейс
  открытой сцены своим `UiLayer` (кнопка UI во вьюпорте, `sceneStore.uiVisible`; выбранные элементы в синей
  рамке), в Play — `game.ui` в виде Game; пока интерфейс показан при правке, нажатие на элемент во вьюпорте
  выбирает его, а протягивание двигает (`onUiDown` / `onUiMove` в `Viewport.tsx`: `UiLayer.elementAt` находит
  верхний элемент с текстом, картинкой или кнопкой, поля `x` и `y` пишутся целыми единицами через
  `setComponentField`); у главного выбранного элемента восемь ручек размера по углам и сторонам
  (`UiLayer.handles`, `UI_HANDLES`; `uiHandleAt`): ручка двигает свою сторону, противоположная стоит — меняются
  `width` / `height` и вместе с ними `x` / `y` на долю, зависящую от якоря (`anchorPoint`), размер 0 («как у
  родителя») при этом становится числом; гизмо у выбранного объекта с `ui` не показывается; `check`: `text`,
  `image`, `button` без `ui`, нет шрифта или картинки. Демо: сцена `ui`, поведение `clicker`.
- **Звук** — файл в `assets/` (mp3, ogg, wav), называется с расширением, как текстура: параметр типа `asset` с
  `kind: "sound"`, список — `registry.setSounds(base, files)` (редактор — `GET .../assets?kind=sound`, сборка —
  `./assets/`, `check` и `render` — имена для проверки). Всё играет `SoundPlayer` (`src/engine/sound.ts`), у
  `Game` он один — `game.sound`; контекст Web Audio один на страницу, расшифрованные файлы хранятся по адресу,
  `Game.start` загружает все звуки проекта заранее. Два способа играть. Компонент `sound` (`sound`, `volume`,
  `pitch`, `loop`, `autoplay`, `spatial`, `range`) кладёт в объект метку с `userData.sound`; `Runtime.sounds()`
  после каждого кадра запускает появившиеся метки с `autoplay` и останавливает звуки убранных и выключенных
  объектов. Из поведения — `self.playSound(name, { volume, pitch, loop, at, range })` (к объекту не привязан,
  возвращает `{ stop(), volume, playing }`) и `self.sound(object?)` — компонент `sound` объекта: `play()`,
  `stop()`, `playing`. Звук с местом (`spatial` или `at`) затихает по расстоянию до нуля на `range` метров и
  уходит в левое или правое ухо; расстояние считается от камеры сцены или от объекта с компонентом
  `listener` (нужен при далёкой камере — изометрия), лево и право — всегда по камере. **Музыка** — единственный звук,
  который переживает смену сцены: поле `music` компонента или `self.playMusic(name, options)` /
  `self.stopMusic()`; она одна (`SoundPlayer.track`), тот же файл не запускается заново, другой занимает его
  место, с объектом она не кончается; у компонента она всегда по кругу (`loop` и `spatial` при `music` скрыты
  и не действуют). Для этого `SoundPlayer` один на весь запуск: `runGame` и редактор
  (`sceneStore.playSounds`) дают его каждому `Game` четвёртым аргументом, `Game.dispose` тогда зовёт
  `endScene()` (всё, кроме музыки), а сам проигрыватель закрывает тот, кто его создал. Это считает сам
  `SoundPlayer.update`, а не `PannerNode`, поэтому работает и запасной путь: файл, который нельзя получить
  `fetch`'ем (игра открыта с диска), играет элемент `<audio>` — без лево / право. Пауза — скорость 0 у
  источника. Браузер молчит до первого нажатия: контекст будится первой клавишей или щелчком.
  `renderStill` звук выключает (`sound.enabled = false`). В редакторе: вид Sounds в панели Project (двойной
  щелчок — послушать, файлы с рабочего стола загружает `uploadFiles`, перетаскивание на объект — `applySound`:
  компонент `sound` с этим файлом), проигрыватель в Inspector, Play → Mute Sound и флажок в Settings → Editor
  (`sceneStore.muted`, только редактор), пауза Play ставит на паузу и звук. Во вьюпорте у объекта со звуком
  значок-динамик, у `listener` — октаэдр (бирюзовые, по ним объект выбирается щелчком; у объекта со светом или
  камерой остаётся их значок), у `spatial` — два круга радиусом `range` в метрах мира: от объекта они берут только место, без масштаба и
  поворота (свой `updateMatrixWorld` у группы кругов в `createHelper`, `SceneStore.ts`). Демо: `coin.wav` и `hum.wav`
  (сделаны кодом), `pickup` звенит при подборе.
- **Переименование материала, Look или префаба** (`renameAsset` в `actions.ts`; поле имени в шапке Inspector, Enter —
  применить, Esc — отменить): пишет файл под новым именем, удаляет старый и сразу переписывает всё, что
  ссылалось на ассет по имени, — сцены и префабы на диске (включая открытую сцену; её несохранённые правки
  остаются несохранёнными), `extends` у Look, поле `prefab` у экземпляров. Ссылки находятся по определениям полей (`type: "asset"`),
  а не по названию ключа. Сцену переименовывает `renameScene`: на неё никто не ссылается, меняется только
  файл (у открытой — тот, что на диске, несохранённые правки остаются несохранёнными). В открытой сцене имя меняется и во всех запомненных состояниях
  (`sceneStore.renameReferences`: снимок «сохранено», шаги undo), поэтому undo старое имя не возвращает.
  Во время Play и правки префаба недоступно.
- **Модель из кода** — `defineModel({...})`, экспортированный из любого файла в `scripts/`. Редактор
  импортирует скрипты через Vite; правка файла перезагружает их без перезагрузки страницы
  (событие `white:scripts-changed`).
- **Поведение** — `defineBehavior({ name, params, start, update })` из `scripts/`, вешается компонентом
  `{ "type": "script", "script": "<имя>", "params": {...} }`. three.js-объекта у него нет: `createEntityObject`
  кладёт скрипты в `userData.scripts` группы (`setScripts`), а `Runtime` обходит дерево и запускает их.
- **Жизнь объектов в игре:** у `self` поведения есть `spawn(prefab, position?, parent?)` — новый экземпляр
  префаба в идущей сцене, его поведения стартуют в том же кадре; `destroy(object?)` — убрать объект (свой,
  если не указан) со всем, что под ним: он исчезает после того, как отработают поведения кадра
  (`Runtime.sweep`), ресурсы освобождаются; `get(name, object?)` — `self` другого поведения на своём или
  чужом объекте, через его `state` поведения и общаются. У `defineBehavior` есть третья функция —
  `destroy(self)`: вызывается при удалении объекта и при остановке игры (`Runtime.dispose`), если `start` уже
  был. Параметр типа `asset` теперь может быть `kind: "prefab"` (список префабов в Inspector, проверка в
  `check`, обновление при переименовании). `Game.update` каждый кадр заново ищет камеру сцены: её могли
  создать, убрать или выключить.
- **Столкновения** — без физики: ничего не падает и не отскакивает. Компонент `collider` (`shape`: `box` с `sizeX` / `sizeY` / `sizeZ`,
  `sphere` с `radius`, `capsule` с `radius` и полной высотой `height`; сдвиг `centerX` / `centerY` /
  `centerZ`; `solid`) кладёт в объект невидимую
  метку с `userData.collider` (её позиция и есть сдвиг); `Runtime` каждый кадр собирает по ним тела
  (`bodies`): куб по осям мира (повёрнутый объект берётся в охватывающий куб) или вертикальная капсула —
  шар считается капсулой нулевой длины, поэтому проверок пересечения всего три.
  `self.move(x, y, z)` двигает объект по одной оси за раз и откатывает ось, если сплошной коллайдер
  упёрся в другой сплошной, — так получается скольжение вдоль стены; то, в чём объект уже застрял, его не
  держит. После поведений кадра `Runtime.collide` сравнивает касания с прошлым кадром и вызывает у
  поведений `enter(self, other)` / `exit(self, other)`; `self.touching()` — кого объект касается сейчас.
  Триггер — коллайдер с `solid: false`. В редакторе коллайдер виден контуром (зелёный — сплошной, жёлтый —
  триггер), щелчком он не выбирается. **Edit Collider** (`sceneStore.colliderEdit`; кнопка во вьюпорте и в
  заголовке компонента) вместо гизмо показывает ручки на коллайдере выбранного объекта
  (`src/components/colliderHandles.ts`): точка на стороне двигает эту сторону (у куба противоположная стоит
  на месте, центр сдвигается на половину), у шара и капсулы меняет радиус или высоту; квадрат в середине
  двигает коллайдер в плоскости экрана. Ручки пишут поля компонента через `setComponentField`, поэтому всё
  видно в Inspector и входит в undo; работают и для объекта внутри экземпляра префаба (как переопределение).
- **Физика** (`src/engine/physics.ts`, библиотека cannon-es — выбор за мной по поручению автора «используем
  сторонний движок» 11.10.2026: чистый JS, синхронная, поэтому `Game`, `renderStill` и прогоны остались
  синхронными; Rapier точнее, но WASM с асинхронным запуском и +2 МБ. Библиотека импортируется только в этом
  файле — замена движка не трогает формат). Компонент `body` (`mass`, `friction`, `bounce`, `damping`,
  `lockRotation`, `gravity`) кладёт метку `userData.body`; тело — объект с ней и сплошным `collider` (форма:
  куб, шар, капсула из цилиндра и двух шаров). Остальные сплошные коллайдеры — кинематические тела: стоят,
  где стоит объект, с настоящим поворотом. `Runtime.update` после поведений зовёт `physics.step(root, dt,
  active)`: тела создаются и пересоздаются по «подписи» (поля, масштаб, сдвиг; скорость при пересоздании
  сохраняется), убранные и выключенные удаляются; кинематическим ставится прошлое место и скорость, с
  которой они доедут до нового за шаг (так игрок расталкивает ящики; скачок больше метра — телепорт);
  `world.step(1/60, dt, 5)`; места динамических тел пишутся обратно в объекты (мир → родитель). Тело,
  которое поведение передвинуло само, продолжает с нового места. Пока в сцене нет ни одного `body`, шаг
  ничего не делает. Материалы: у не-тел трение и отскок 1, cannon перемножает пару — значит действуют поля
  тела. Слои → биты `collisionFilterGroup` / `Mask` (до 31 слоя). Сон включён (стопка не ползёт). Гравитация —
  `gravity` в `project.json` (по умолчанию 20, как у `fall`). `self.move`: по горизонтали тела не препятствие
  (в них входят, физика их выталкивает), по вертикали — препятствие (на ящике можно стоять); флаг
  `Body.dynamic` и `firm` в `obstacles`. Из поведений — `self.body(object?)`: `velocity`, `setVelocity`,
  `push`, `setSpin`. `check`: `body` без коллайдера или с триггером. Демо: сцена `physics`.
- **Игровая математика** (всё в `runtime.ts`, для поведений — методы `self`). `raycast(origin, direction,
  options)` — луч по тем же телам, что и столкновения (`rayBody`: куб — по трём парам сторон, капсула — бок
  плюс два шара); опции `distance`, `layers`, `triggers`, `ignore` (по умолчанию свой объект); тело, внутри
  которого луч начался, не считается. `screenRay(x?, y?)` — луч из камеры сцены через точку экрана
  (`Runtime.camera` обновляет `Game`). `findAll(query)` / `find(query)` — активные объекты по `tag`, `name`,
  `behavior`. Гравитация без физики: `fall(dt, gravity = 20)` каждый кадр двигает объект вниз через `move` с
  накопленной скоростью (`Runtime.speeds`), `jump(speed)` её задаёт, `grounded()` пробует сдвиг вниз на 5 см.
  **Ступеньки:** `self.move(x, y, z, step)` — упёршись по горизонтали, объект, стоящий на опоре, пробует тот же
  шаг на `step` метров выше и, если там свободно, опускается на уступ (`Runtime.stepUp`); в прыжке не
  действует. Демо-поведение `walker` (клавиши, стик, прыжок, падение, ступеньки).
  `move` теперь идёт шагами не длиннее 0.25 м (`MAX_STEP`) и, упёршись, делением шага пополам встаёт вплотную
  к препятствию — раньше останавливался, не дойдя на длину кадра.
- **Теги** — поле `tag` объекта (любое слово): `createEntityObject` кладёт его в `userData.tag`, экземпляр без
  своего тега берёт тег корня префаба (`expandInstance`). В Inspector — поле Tag с подсказкой из тегов сцены
  (`sceneStore.setTag`, `sceneStore.tags`); у объекта из префаба оно закрыто.
- **Слои столкновений** — как в Unity, но слой у коллайдера, а не у объекта: поле `collider.layer` (параметр
  типа `asset` с `kind: "layer"`, пусто — слой `Default`). Слои и матрица лежат в настройках проекта
  `projects/<имя>/project.json`: `{ "layers": [...], "noCollision": [["A", "B"]] }` — перечислены пары, которые
  друг друга не замечают (ни упора в `move`, ни `enter` / `exit`); остальные сталкиваются. Всё про файл — в
  `src/engine/settings.ts` (`parseSettings`, `validateSettings`, `layersCollide`, `setLayersCollide`), в игре —
  `registry.settings`. Файл читают редактор (API `GET` / `PUT /__api/projects/<имя>/settings`, правка извне
  перезагружает проект), `check`, `render` и сборка игры. В редакторе: раздел Collision Layers
  — список слоёв и таблица флажков по парам; `updateSettings` в `actions.ts`
  пишет файл сразу; это шаг undo. Сам раздел — на странице Project окна Settings; имя слоя там правится в
  поле (Enter): `renameLayer` переписывает настройки и поле `layer` коллайдеров в сценах и префабах на диске и
  в открытой сцене (сам переименованием в undo не входит).
- **Console** — отдельное плавающее окно поверх редактора (`src/editor/Console.tsx`, данные в `src/editor/core/log.ts`):
  `captureConsole()` из `main.tsx` подменяет `console.log / info / warn / error` и слушает необработанные
  ошибки окна, так что туда попадает всё, что печатают скрипты, ошибки поведений (`Runtime.report` пишет имя
  скрипта и объекта) и ошибки шейдеров three.js. Одинаковые сообщения подряд складываются со счётчиком,
  хранится 500 последних, длинные обрезаются; сообщения dev-сервера (`[vite]`) пропускаются. Play очищает
  Console. Окно двигают за заголовок, размер меняют за правый нижний угол (CSS `resize`), место и размер
  запоминаются в браузере (`white:console-window`); редактор под ним продолжает работать. В заголовке —
  число ошибок и предупреждений, корзина и крестик. Открыть и закрыть — слово Console слева в строке статуса
  (`ConsoleButton`; рядом число ошибок и предупреждений, видно и при закрытом окне) или Window → Console
  (`sceneStore.consoleOpen`, запоминается в браузере; по умолчанию закрыто).
- **Настройки проекта** (`project.json`, всё про файл — в `src/engine/settings.ts`): `startScene`, `aspect`
  (`free`, `16:9`, `16:10`, `4:3`, `1:1`, `9:16`), `tags`, `layers`, `noCollision`; значения по умолчанию в
  файл не пишутся (`serializeSettings`). `aspect` — форма картинки игры: `fitAspect` даёт область в середине,
  `runGame` ставит туда канвас, вьюпорт в виде Game рисует в эту область через `setViewport` / `setScissor`
  (остальное чёрное; `sceneStore.gameArea`), мышь игры считается по ней (`Input.area`); вид из выбранной
  камеры получает ту же форму. `tags` — общий список тегов: Inspector предлагает их, а `check` (и
  `validateScene`) считает ошибкой тег не из списка; пустой список разрешает любой. Страница Project окна
  Settings: разделы Game, Tags, Collision Layers.
- **Сцены в игре:** идёт всегда одна. `self.loadScene(name)` ставит `Runtime.requestedScene`; тот, кто крутит
  игру, после `update` видит `game.requestedScene`, убирает `Game` и создаёт новый с теми же `globals`
  (`self.globals` — общий объект, который живёт от сцены к сцене). `runGame(container, registry, scenes,
  start)` принимает все сцены проекта; сборка кладёт их все. В редакторе Play делает то же через
  `sceneStore.enterScene`: сцена читается с диска (`sceneLoader`), `playScene` — её имя (видно в значке
  Playing), а Hierarchy и Inspector остаются на открытой сцене; правка её дерева возвращает Play в неё.
  Параметр типа `asset` с `kind: "scene"` — список сцен (`registry.setScenes`).
- **Проверка перед сборкой:** в редакторе File → Build Game сначала вызывает `validateProject` (сцены, префабы,
  материалы, Look с диска через те же `validate*`; типы скриптов не проверяются) — проблемы уходят в Console,
  сборка отменяется. `npm run build:game` сначала запускает `check`; `--no-check` — собрать всё равно. Стартовая
  сцена сборки: указанная в команде, иначе `startScene`, иначе `main`, иначе первая; из редактора —
  `startScene`, а без неё открытая сцена.
- **Объекты, созданные в Play** (`self.spawn`): `sceneStore.spawned` находит в запущенной сцене объекты,
  которых не было при старте; Hierarchy во время Play опрашивает его дважды в секунду и показывает списком
  «Created in Play».
- **Настройки редактора** (привязка и её шаг, оси гизмо, показ Look) хранятся в браузере (`white:editor`).
- **Шаги undo для ассетов** теперь шире: кроме материалов и Look — `folders` и `settings` (весь файл до и
  после), `scenes` (удаление), `prefabs` (создание, удаление, Apply); всё проходит через
  `sceneStore.recordAsset` и `assetHandler` в `actions.ts`.
- **Особенности компонента описаны в его определении**, а не проверками `type === ...` по коду:
  `create` (нет — компонент ничего не рисует), `source` (содержимое берётся по имени из `scripts/`, его
  параметры лежат в `component.params` — так устроены `model` и `script`), `multiple` (можно несколько на
  объекте). Компонент внутри объекта адресуется ключом `componentKey()`: тип (`"mesh"`) или
  `"script:spin"` для `multiple`. Этим же ключом помечен его three.js-объект (`userData.component`),
  по нему работают методы store (`addComponent`, `removeComponent`, `setComponentField`,
  `setComponentParam`), ключи React и поиск дублей в валидации.
- **Play** (`sceneStore.play()` / `stop()`, кнопка в середине верхней полосы — `.topbar-play` в `Toolbar.tsx`, меню Play, Ctrl+P): store создаёт `Game` из данных сцены —
  отдельную копию объектов, собранную тем же кодом движка, что и игра. Вьюпорт рисует `sceneStore.viewScene`
  (сцена игры во время Play, иначе сцена редактора); какой камерой — см. «Два вида» ниже. Объекты
  редактора скрипты не трогают. В копии нет сетки и маркеров. Кадры двигает вьюпорт (`sceneStore.tick`).
  В режиме префаба Play недоступен.
- **Правка во время Play** разрешена и видна сразу. Методы store меняют данные сцены и тут же копию:
  transform, имя, active — `game.syncEntity`, компоненты — `game.syncComponent` (вызывается из
  `rebuildComponent`), окружение — `game.setEnvironment`. Параметры скрипта `Runtime` читает прямо из
  данных компонента, поэтому их правка не сбрасывает состояние поведения. Изменения дерева (добавить,
  удалить, перенести объект, префаб ↔ объект) пересобирают копию заново (`restartGame`) — состояние
  поведений при этом сбрасывается. Гизмо в Play переезжает в сцену копии и держит её объект
  (`selectedViewObject`); `syncFromGizmo` пишет в данные только то, что меняет текущий режим гизмо
  (позицию, поворот или масштаб), чтобы не сохранить то, что накрутил скрипт.
- **Два вида в Play, как вкладки Unity:** переключатель Scene / Game во вьюпорте (`sceneStore.playCamera`).
  Play всегда стартует в Game: камера сцены (`Game.camera`: первый активный объект с компонентом `camera`),
  клавиши и мышь идут в игру — выглядит и играется как собранная игра; выбор кликом, гизмо, меню и полёт
  выключены (`sceneStore.gameView`). Scene — камера редактора с выбором и гизмо, чтобы подвинуть что-то на
  ходу. Сцена работает в обоих видах, Hierarchy и Inspector правят её в обоих. Если камеры в сцене нет,
  вида Game нет, Play идёт в Scene.
- **Пауза и шаг** (`sceneStore.paused`, `togglePause()`, `step()`; кнопки в верхней полосе, Ctrl+Shift+P и
  Ctrl+Alt+P): на паузе `tick` не двигает игру; шаг ставит паузу и двигает сцену на один кадр (1/60 с).
  Пауза возвращает полный редактор: `sceneStore.gameView` на паузе ложно, поэтому вьюпорт показывает
  запущенную сцену камерой редактора — вращение, полёт по W/A/S/D, выбор, гизмо, меню, клавиши редактора;
  ввод игры отключён. Снятие паузы возвращает вид Game (если он был выбран).
- **Ввод: мышь, пальцы, геймпад** (`src/engine/input.ts`). Кроме клавиш у `Input` есть указатели
  (`pointers`): 0 — мышь и первый палец (он же двигает `mouseX` / `mouseY` и «левую кнопку», так что написанное
  под мышь работает на телефоне), у остальных пальцев свои номера (`touches`); канвасу на время игры ставится
  `touch-action: none`. Кнопки интерфейса считаются по каждому указателю отдельно (`UiLayer.update`: `grabs`
  — на какой кнопке указатель нажал; нажал и отпустил на одной — щелчок), и пока кнопку держат, в её полях
  `held = true` — из этого делаются экранные кнопки под несколько пальцев. Геймпад: `Game.update` первым делом
  зовёт `input.poll()` (событий у геймпада нет), кнопки первого геймпада становятся клавишами `Pad0`…`Pad16`,
  стики — `input.stick("left" | "right")` с мёртвой зоной 0.15 и `y` вверх. Захват мыши —
  `lockPointer()` / `unlockPointer()` / `pointerLocked`: браузер даёт его только по щелчку, поэтому запрос
  повторяется при следующем нажатии на канвас; `detach` его отпускает. Всё это можно подать руками:
  `setPointer(id, x, y, down, touch)`, `setPad(buttons, axes)`.
- **Ввод:** у `Game` есть `input` (`Input`), поведения читают его как `self.input`. В редакторе канвас
  подключается к нему (`input.attach`) только в виде Game (`sceneStore.gameInput`); в виде Scene клавиши и
  мышь принадлежат редактору. В виде Game горячие клавиши редактора, кроме Ctrl+P и Ctrl+S, отключены.
  Нажатия в текстовых полях до игры не доходят.
- **Stop** (`requestStop`): если сцена изменилась с момента Play (сравнение с JSON-снимком `playSnapshot`),
  спрашивает Keep / Discard / Continue playing. `stop(true)` оставляет правки, `stop()` возвращает снимок.
  Автоматические остановки (загрузка сцены, вход в префаб) правки отбрасывают. Сохранение сцены и
  Create Prefab во время Play запрещены: правки ещё могут быть отброшены. Правка скрипта, материала или
  префаба на диске перезапускает Play.
- **Look** — ассет `looks/<имя>.json`: `pixelSize`, `toneMapping`, `exposure`, списки `surfaces` и `effects` и
  необязательный `extends` (стиль построен на другом). Сцена ссылается на него полем `environment.look`.
  Эффект — `defineEffect({ name, params, inputs, shader })`: кусок GLSL, определяющий
  `effect(uv, color)`; параметры становятся uniform'ами с теми же именами. Встроенные (`outline`,
  `palette`, `grade`, `vignette`) написаны этим же способом и зарегистрированы в каждом `Registry`;
  эффекты проекта приходят из `scripts/` через `registerExports`. `RenderPipeline` рисует сцену в
  полуплавающие текстуры (линейный цвет), при надобности — второй раз с материалом нормалей, прогоняет
  эффекты по очереди и выводит на канвас с переводом в sRGB. Без Look (или с пустым) это обычный
  `renderer.render`. Шейдеры пересобираются только при смене списка эффектов, числа меняются на лету.
  В редакторе: вкладка Looks в Project, `LookInspector` (унаследованные эффекты помечены, их правка
  пишется в этот Look, базовый не трогается). Во вьюпорте — список выбора Look сцены и кнопка-глаз
  (`sceneStore.lookEnabled`), которая выключает Look только для вьюпорта. «Standard (no effects)» в списке —
  сцена без Look, обычный рендер three.js.
- **Поверхность** (`surfaces` в Look) — добавка к материалам всей сцены: то, чего нельзя сделать с готовой
  картинкой. `defineSurface({ name, params, defines, vertex, fragment })`: `vertex` определяет
  `surfaceVertex(clip)` (место вершины на экране), `fragment` — `surfaceColor(color, albedo)` (освещённый
  цвет), `defines` включает переключатели шейдеров three.js. Встроенные: `vertexSnap` (дрожание вершин PS1),
  `toon` (свет полосами), `flat` (плоские грани). Материалы никто не регистрирует: `Surfaces.prepare` перед
  каждой картинкой обходит видимые меши сцены и ставит материалам `onBeforeCompile` — так охвачены и
  материалы проекта, и те, что создают модели из кода; у материала без шейдерных кусков three.js (свой
  `ShaderMaterial`) ничего не меняется. Все поверхности стиля попадают в один шейдер, их параметры и
  функции разведены по именам через `#define`. Uniform'ы общие на все материалы: числа меняются на лету,
  шейдеры пересобираются только при смене списка. Без стиля (или с выключенным глазом) `restore` возвращает
  материалам исходный вид. Материал нормалей для контуров получает те же `vertex` и `defines`.
- **Ортографическая камера и привязка к пикселям.** У компонента `camera` есть `projection`
  (`perspective` / `orthographic`) и `size` — половина высоты видимой области в метрах; ширину под форму
  экрана подгоняет `setCameraAspect` (общая для `Game.resize`, вида из камеры и `renderStill`). Привязка
  (`pixelSnap` в Look, включена по умолчанию) действует с ортографической камерой и `pixelSize` больше 1:
  `RenderPipeline.snapCamera` на время кадра сдвигает камеру в ближайшую точку, кратную размеру пикселя
  уменьшенной картинки, — неподвижный мир попадает в те же пиксели, пока камера едет. Отброшенный остаток
  сдвига добирается на выводе смещением картинки (`offset` в последнем шейдере), так что движение остаётся
  плавным. Эффектам доступен `scroll` — на сколько пикселей ушла камера: узор от `uv * resolution + scroll`
  держится за мир, а не за экран (так считают dither у `palette` и штрихи у `hatch`). `depthAt` для
  ортографической камеры считает глубину линейно (`cameraOrtho`). Камера редактора остаётся перспективной.
- **Инструменты редактора рисуются после Look** и эффектами не задеваются. Сетка и маркеры света и камеры
  лежат на слое three.js `EDITOR_LAYER` (1): вьюпорт рисует картинку камерой со слоем 0, затем на канвасе
  заново пишет глубину сцены (материал без записи цвета) и поверх — слой редактора, так что объекты его
  заслоняют. Гизмо остаётся на слое 0 (иначе его не ловит луч `TransformControls`), прячется на время
  картинки и рисуется последним. У сцены с цветным фоном three.js очищает канвас при каждом `render`,
  поэтому на эти проходы `scene.background` снимается.
- **Build:** `buildGame` собирает Vite'ом один файл `game.js` (формат IIFE, обычный `<script>`): движок,
  three.js, все скрипты проекта, материалы, префабы, настройки и все сцены — и вызывает `runGame` со стартовой. Рядом
  пишется `index.html`, папка `assets/` копируется как есть. Результат — `projects/<имя>/build/` (в
  `.gitignore`), открывается с диска без сервера. Точка входа — виртуальный модуль, временных файлов нет.
  В редакторе пункт File → Build Game (собирает с открытой сцены; несохранённая сцена — отказ) и ссылка Open game на
  `/__game/<имя>/`, где dev-сервер раздаёт сборку как есть. Папки `build` исключены из слежения Vite.
- **Прогон с нажатиями** (`npm run render -- demo iso --input "KeyD@0-1 click:Add@2" --state`): та же команда
  `render` играет сцену со сценарием игрока и печатает итог — чтобы агент проверял геймплей, а не только кадр.
  `--input` разбирает `tools/render.mjs` в список `PlayEvent` (`{ at, key, down, mouse }`; запись
  `<клавиша>@<с>-<по>`, `<клавиша>@<когда>`, `click:<имя или x,y>@<когда>`, `mouse:<...>@<когда>`), `renderStill`
  (`options.inputs`) перед каждым кадром подаёт подошедшие события в `game.input`; щелчок по имени находит
  середину элемента интерфейса (`game.ui.placeOf`) или проецирует объект через камеру сцены. `--state`
  (`options.state`) возвращает `Still.state`: каждый объект (имя, место в мире, активен ли, текст) и
  `self.globals`. Страница перехватывает `console.log / warn / error` и печатает их строками `log:`. Шаг кадра
  ровно 1/60 с.
- **Render** (`npm run render -- <проект> [сцена]`): картинка сцены без редактора — чтобы агент видел, что
  получилось. Опции: `--out`, `--size`, `--time` (сколько секунд сцена «играет» до снимка), `--camera` /
  `--target` / `--fov` (вместо камеры сцены), `--look` / `--no-look`. Рисует `renderStill` из движка — те же
  `Game`, Look и `RenderPipeline`, что в игре; без камеры в сцене ставит её сам по размерам сцены. WebGL
  нужен браузер, поэтому `tools/render.mjs` запускает установленный Chrome или Edge в режиме без окна (путь
  к другому — в `WHITE_BROWSER`) с отдельным временным профилем и отдельным кэшем Vite
  (`node_modules/.vite-render`), чтобы не мешать открытому редактору; новых зависимостей нет. Страница
  шлёт PNG обратно POST-запросом. Ошибки шейдеров (`renderer.debug.onShaderError`), исключения поведений и
  несуществующий Look печатаются как `problem:` и дают код выхода 1. Папка `renders/` — в `.gitignore` и вне
  слежения dev-сервера.
- **Префаб** — `prefabs/<имя>.json` с `root`. Экземпляр в сцене — объект с полем `prefab` и своим
  transform; содержимое берётся из файла. Объекты внутри экземпляра не имеют `entityId`, поэтому клик
  во вьюпорте выбирает экземпляр целиком.
- **Переопределения** — поле `overrides` экземпляра: `{ "<путь из имён от корня префаба>": { active,
  position, rotation, scale, components: { "<ключ компонента>": { поля } } } }`, `"."` — корень.
  Ключ `name` даёт объекту префаба другое имя в этом экземпляре: пути и id по-прежнему идут по имени из
  префаба, новое имя ставится в самом конце (`renames` и `applyRenames` в `prefab.ts`; вложенный экземпляр
  разворачивается с `final = false`, чтобы имена ставил только внешний). `expandInstance` даёт
  экземпляр как обычный объект: содержимое префаба плюс переопределения; так его строит `createEntityObject`,
  так же его видят `Runtime` и валидация. Объекты внутри получают id `"<id экземпляра>/<путь>"` (на three.js-
  объекте — `userData.innerId`), по ним их знают `sceneStore.objects` и `Game.objects`, поэтому гизмо и
  правка в Play работают как с обычными. Путь, уходящий во вложенный экземпляр другого префаба, переносится
  в его собственные `overrides`. В редакторе: экземпляр в Hierarchy раскрывается (по умолчанию свёрнут), его
  внутренности — курсивом, изменённые — жирным; их можно выбрать и править в Inspector или гизмо. Методы
  store не пишут переопределения сами: `locate(id)` даёт копию объекта с применёнными переопределениями,
  метод правит её как обычный объект, `commit` сравнивает с префабом (`diffOverride`) и записывает разницу в
  экземпляр — вернул значение как в префабе, переопределение исчезло. Компоненты самого экземпляра
  (корня префаба) правятся так же (`locate(id, true)`). Revert — `revertOverrides(id)`. Unpack сохраняет
  переопределения в получившихся объектах. Изменённые поля в Inspector помечены (синяя жирная подпись,
  `sceneStore.overrideOf(id)`); правый щелчок по такой подписи — Revert to Prefab для одного поля
  (`revertOverrideField`). Apply (`applyOverrides(id)` в `actions.ts`, кнопки в Inspector и пункты
  контекстного меню) вписывает переопределения в префаб (`applyToPrefab`), сразу пишет файл префаба и
  убирает их из экземпляра: для экземпляра — все, для объекта внутри — только его. Во время Play и для
  префаба, открытого на редактирование, Apply недоступен. Режим редактирования префаба показывает его отдельной сценой, сцена
  ждёт в `stash`; выход сохраняет префаб.
- **Добавленное и убранное в экземпляре** — ещё четыре ключа той же записи `overrides["<путь>"]`:
  `addComponents` (список компонентов), `removeComponents` (список ключей), `addChildren` (список обычных
  объектов, пишутся целиком) и `removed: true` (объекта префаба в экземпляре нет). Всё применяет `applyAt` в
  `prefab.ts`: сначала `removed`, потом убранные и добавленные компоненты, правки полей, добавленные дети;
  для вложенного экземпляра другого префаба запись передаётся в его собственные `overrides` (`mergeOverride`).
  Компоненты идут прежним путём: метод store правит копию из `locate`, `diffOverride` сам находит, чего в
  префабе нет (`addComponents`) и что пропало (`removeComponents`). Объекты устроены иначе — **добавленный
  объект настоящий**: он лежит в `addChildren` экземпляра и правится напрямую, без `commit` (тот лишь не
  теряет `addChildren`). Его id не случайный, а выводится из места: `"<id того, в чём он лежит>/<имя>"`, и так
  же вниз по его детям — ровно те id, что ставит `expandInstance`, поэтому объекты three.js, `Game` и выделение
  находят его как раньше. Id назначает `assignAddedIds` (вызывается в `rebuild()`, выделение переезжает на
  новые id); объект, вынутый из экземпляра, получает обычный id. Поэтому `/` в id больше не значит «из
  префаба»: это решают `sceneStore.isInner(id)` (не настоящий объект, но лежит в экземпляре),
  `realEntity(id)`, `addedIn(id)`, `pathIn(id)`; модульный `findEntity` заходит и в `addChildren` и отдаёт
  `parentId` — id того, под чем объект лежит (у добавленного это не настоящий объект). Куда встанет новый
  объект, решает `slot(parentId)`: под экземпляром или под объектом префаба — в `addChildren` нужного пути.
  Правки, меняющие состав экземпляра (вставка, удаление, перенос, переименование добавленного, Revert),
  заканчиваются `restructure()` — уборка пустых записей и полная пересборка объектов сцены.
  `removeEntity` для объекта префаба пишет `removed` и стирает переопределения под ним; `restoreRemoved` и
  `restoreComponent` возвращают. В редакторе: под объектом префаба и под экземпляром можно создавать детей
  (меню, перетаскивание строки в Hierarchy, Ctrl+D на объекте префаба делает добавленную копию), Del и корзина
  убирают объект префаба из экземпляра; в Hierarchy добавленный помечен «+», убранный показан зачёркнутой
  строкой с кнопкой возврата; в Inspector у объектов экземпляра работают Add Component и крестик компонента,
  добавленный компонент выделен в заголовке, убранные перечислены с кнопкой Restore. Apply переносит всё это
  в файл префаба, Revert убирает. `check` проверяет новые ключи (нет такого компонента, компонент уже есть в
  префабе, совпадение имён, `removed` у корня).
- **Undo / redo** (`sceneStore.undo()` / `redo()`, кнопки в Toolbar, Ctrl+Z, Ctrl+Y или Ctrl+Shift+Z) — снимками:
  любая правка данных сцены кончается в `notify()`, там `record()` сравнивает JSON сцены с прошлым и кладёт
  прошлый в стек (до 100 шагов). Новым методам store ничего делать не надо. Правки, идущие чаще чем раз в
  400 мс (перетаскивание гизмо, набор числа), сливаются в один шаг. Откат заменяет данные и пересобирает
  объекты (`restore`, тот же код, что у Stop без Keep); во время Play перезапускает копию. Загрузка сцены
  (в том числе перезагрузка с диска после внешней правки) историю сбрасывает; у префаба своя история, история
  сцены ждёт в `stash`. Отброс правок при Stop — тоже шаг, его можно отменить. Выделение в историю не входит.
  В том же стеке лежат шаги ассетов — правка, создание и удаление материала или Look: их записывает
  действие в `actions.ts` (`sceneStore.recordAsset(section, name, before, after)`, `null` — ассета нет), а
  откат выполняет `sceneStore.assetHandler` (реестр и файл на диске). Шаги сцены и ассетов отменяются в том
  порядке, в каком были сделаны; сливаются только соседние правки одного и того же.
- **Вид из камеры:** пока выбран объект с компонентом `camera` (и нет Play), вьюпорт рисует в правом нижнем
  углу то, что видит эта камера (`sceneStore.previewCamera`): тем же `RenderPipeline` и с тем же Look, в
  области канваса, заданной `setViewport` / `setScissor`. Рамка и имя — элемент `.viewport-preview` поверх.
- **Панель Project:** вкладки Scenes, Materials, Prefabs, Models, Looks и Scripts. Scripts показывает то, что
  определено кодом и не является файлом-ассетом: поведения, эффекты и поверхности (встроенные помечены
  built-in). Выбор такой плитки открывает в Inspector параметры с типами и значениями по умолчанию и список
  «где используется» (Look для эффектов и поверхностей, объекты открытой сцены для поведений); двойной щелчок
  вешает поведение на выбранный объект или добавляет эффект / поверхность в Look сцены (`addToLook`).
  Поведение можно перетащить на объект. Правый щелчок по плитке — меню по типу (Open, Edit Prefab, Add to
  Scene, Use in This Scene, Duplicate, Delete), по пустому месту — New Scene / Material / Look. Duplicate
  (`duplicateAsset`) есть у материалов и Look и входит в undo. `AssetRef.kind` включает `behavior`, `effect`,
  `surface`, хотя файлов у них нет.
- **Папки в панели Project** — только раскладка: файлы ассетов остаются на местах, имена уникальны на весь
  проект, ссылки по имени не меняются. Что в какой папке лежит, записано в `projects/<имя>/folders.json`:
  `{ "materials": { "Walls": ["Bricks", "Stone"] } }`; разделы — `scenes`, `materials`, `prefabs`, `looks`,
  `textures`. Папка в папке — путь в имени: `"Walls/Old"`; папка, которая есть только как часть такого пути,
  тоже существует (`folderPaths`). Чистые функции — в `src/editor/core/folders.ts` (`placement`,
  `moveToFolder`, `renameInFolders`, `changeFolder`, `folderPaths`, `renameFolderTree`, `removeFolderTree`), состояние — `sceneStore.folders`, запись — действия
  `createFolder`, `renameFolder`, `deleteFolder`, `moveAssetToFolder` в `actions.ts` (API
  `GET` / `PUT /__api/projects/<имя>/folders`). В панели слева дерево: виды ассетов (Scenes,
  Materials, Textures, Prefabs, Models, Looks, Scripts) и под каждым его папки, вложенные — глубже; справа —
  то, что лежит в выбранном месте: плитки вложенных папок и ассеты. Ассет кладётся в папку перетаскиванием
  на её строку в дереве или на её плитку, на строку вида — вынимается наверх; то же пунктами Move to … /
  Take Out of Folder в меню ассета. Создаётся всё в открытой папке: кнопка «+» и меню пустого места (New
  Material / Look / Scene, New Folder…), те же пункты в меню папки вместе с Rename… и Remove Folder
  (`renameFolderTree` переносит и вложенные папки; `removeFolderTree` убирает папку с вложенными, их ассеты
  переходят в папку выше). Переименованный ассет остаётся в своей папке. Имя, которого в проекте нет, панель
  пропускает (так удалённый ассет после undo возвращается в свою папку). Правку
  `folders.json` извне редактор подхватывает
  (`white:folders-changed`), `check` проверяет форму файла и имя в двух папках сразу.
- **Правая часть панели Project:** сверху путь к открытому месту («Materials › Walls › Old», по частям можно
  щёлкать), кнопка «+», поиск по именам ассетов этого вида (ищет во всех папках сразу, у найденного подписана
  его папка) и переключатель вида: плитки или компактный список (`.tiles.list`; запоминается в браузере,
  `white:project-view`). Вкладок больше нет: вид ассетов выбирается в дереве, подсказка о нём — всплывающий
  текст строки. Ширина дерева тянется за его границу (`layout.tree`, тот же `Splitter`; раскладку панели получает от `App`).
- **Меню ассета в панели Project** (правый щелчок), сверх действий по типу: Assign to Selected Object(s) у
  материала (выделение объектов запоминается до того, как щелчок выберет ассет), Select in Scene (N) —
  выбрать объекты, которые используют материал, префаб, поведение или модель (`sceneStore.usersOf`; внутрь

  папкам, Copy Name, Copy Path (`projects/<имя>/materials/Wood.json` — удобно отдать агенту) и Show in Explorer.
  У того, что определено скриптами, файла нет — открывается папка `scripts/`; у встроенного в движок есть
  только Copy Name. Меню пустого места и строки вида в дереве: создание, Show <папка>/ in Explorer, Show
  Project in Explorer (он же в File).
- **Show in Explorer:** `POST /__api/projects/<имя>/reveal?path=...` — dev-сервер запускает проводник системы с
  выделенным файлом (`explorer.exe /select,` на Windows, `open -R` на macOS, `xdg-open` папки на Linux); путь
  обязан оставаться внутри папки проекта, для несуществующего файла открывается ближайшая существующая
  папка. В редакторе — `showInExplorer(path)` в `actions.ts`.
- **Подтверждение необратимого:** удаление сцены или префаба (в undo оно не входит) спрашивает `confirmAt` —
  маленькое меню на месте щелчка с вопросом и одним пунктом Delete; щелчок мимо — отказ.
- **Выделение нескольких объектов:** `sceneStore.selectedIds` — все выбранные, последний — главный
  (`selectedId`: его показывает Inspector и держит гизмо). Ctrl-щелчок в Hierarchy или во вьюпорте
  добавляет или убирает объект, Shift-щелчок в Hierarchy берёт диапазон строк. Shift + протягивание во
  вьюпорте — рамка (`src/components/marquee.ts`, `entitiesInRect`): выбирает всё, чего она касается на экране,
  с Ctrl — добавляет к выбранному. Объект берётся по коробкам своих мешей (каждая отдельно; дочерние объекты
  не в счёт, поэтому пустой родитель не выбирается), заслонённые тоже — как в Unity. Групповые действия идут по
  `selectedRoots` (выбранные, не лежащие внутри других выбранных): Delete, Ctrl+D (`duplicateSelected`),
  Ctrl+G (`groupSelected` — под новый пустой объект в их середине), перетаскивание в Hierarchy, контекстное
  меню. Гизмо двигает всех (`moveOthers`): сдвиг — на то же расстояние в мире, поворот и масштаб — вокруг
  главного объекта, так что группа крутится и растёт как одно целое. Во вьюпорте у каждого выбранного рамка (белая у главного). Inspector при нескольких
  (`MultiInspector`) показывает действия, Active, Transform и компоненты, которые есть у всех выбранных
  (по `componentKey`); значения — главного объекта, там, где у остальных другое, стоит «—» (у флажка —
  промежуточное состояние). Введённое значение уходит всем: те же `TransformSection` и `ComponentSection`,
  что и для одного объекта, только со списком, вызывают обычные методы store для каждого внутри
  `sceneStore.batch(...)` — слушатели и undo видят одну правку. Параметры модели показаны, пока модель у всех
  одна. Крестик в заголовке убирает компонент у всех; Add Component для нескольких нет.
- **Hierarchy:** строку можно бросить на верхнюю или нижнюю четверть другой — она встанет над ней или под
  ней (`sceneStore.moveBeside`; так меняется порядок объектов в сцене и в файле), на середину — станет её

  выключает объект (`setActive`); у выключенного он виден всегда, у остальных — при наведении.
- **Копирование и вставка:** Ctrl+C / Ctrl+X / Ctrl+V (события `copy` / `cut` / `paste` в `App.tsx`) и пункты
  меню. В буфер идёт текст — JSON объектов, как в файле сцены (`copySelected`), поэтому вставлять можно между
  сценами, вкладками и из текстового редактора, в том числе написанное руками (`paste` читает так же, как
  файл сцены: значения по умолчанию можно не писать). Вставленное получает новые id и встаёт рядом с
  выбранным объектом.
- **Привязка гизмо** (`sceneStore.snap`, кнопка-магнит во вьюпорте): сдвиг шагами `snapStep` (0.1–2 м, список
  рядом с кнопкой), поворот по 15°, масштаб по 0.25.
- **Текстуры в панели Project:** вкладка Textures — картинки `assets/` с миниатюрами. Файлы, брошенные в
  панель с рабочего стола, пишутся в `assets/` (`uploadTextures`, API `PUT /__api/projects/<имя>/assets/<файл>`;
  имя приводится к латинице, цифрам, `_`, `-`). Текстура, брошенная на объект с мешем, даёт ему материал с
  ней (`applyTexture`: берётся материал с этой текстурой или создаётся новый, названный по файлу). Удаление —
  с подтверждением.
- **Верхняя полоса:** слева меню, имя проекта (сменить проект — File → Open …; списка проектов в полосе больше
  нет) и выбор сцены с точкой «не сохранено»; ровно по центру окна — Play / Pause / Step (крупные, Play зелёный,
  во время игры кнопка залита; в окне уже 1340 px они встают сразу за сценой); справа undo / redo и
  шестерёнка настроек. Save, Save As, Build и Open game — только в меню File (и Ctrl+S); пока идёт сборка, в
  полосе надпись «Building the game…».
- **Строка меню** — слева в верхней полосе (`Toolbar.tsx`, массив `menus`): File (сцена, сборка, проекты,
  Project Settings), Edit (undo / redo, действия с выбранным, Editor Settings), Object (то же меню создания, что
  у кнопки Create; при одном выбранном объекте новый становится его ребёнком), Play, Window (страницы
  настроек, сброс размеров панелей), Help (управление). Список открывается тем же `openContextMenu`, что и
  контекстные меню, прямо под названием. Недоступное сейчас показано серым (`ContextItem.disabled`); пока одно меню открыто, остальные
  открываются наведением (`contextMenuOwner`).
  Без открытого проекта есть только File.
- **Окно Settings** (`src/editor/SettingsWindow.tsx`; `sceneStore.settingsPage`, `openSettings(page | null)`) —
  всё, что настраивается один раз и не является свойством выбранного: страницы Project (сведения о проекте и
  слои столкновений с матрицей — `LayersSection`), Scene (окружение открытой сцены, те же поля, что в
  Inspector без выделения), Editor (привязка и оси гизмо, показ Look во вьюпорте, сброс размеров панелей —
  `resetLayout`), Controls (шпаргалка по мыши и клавишам, список `CONTROLS` в том же файле — при смене
  управления править и его). Открывается из меню, шестерёнкой в верхней полосе и кнопкой в Inspector без
  выделения; закрывается Esc, крестиком или щелчком мимо. Пока окно открыто, горячие клавиши редактора

- **Размеры панелей:** границы Hierarchy, Inspector, панели Project и дерева в ней тянутся мышью (`Splitter` в

  `--bottom-height` на `.app` и запоминаются в `localStorage` браузера (`white:layout`), не в проекте.
  Проверено настоящей мышью (все три границы, канвас вьюпорта подстраивается) и перезагрузкой страницы.
- **Поле числа** (`NumberInput` в `Inspector.tsx`): значение можно ввести, менять двумя стрелками, которые
  появляются у правого края при наведении, или протянуть — нажать на поле и вести мышь влево-вправо

## Управление

- Левая кнопка: клик — выбор, перетаскивание — вращение камеры, с Shift — рамка выделения (с Ctrl + Shift
  добавляет к выбранному). Средняя — сдвиг, колесо — приближение.
- Зажатая правая кнопка: осмотр мышью, W/A/S/D — полёт, Q/E — вниз/вверх, Shift — быстрее.
- Щелчок правой кнопкой — контекстное меню (Hierarchy и вьюпорт).
- Без правой кнопки: W/E/R — перемещение/поворот/масштаб, F или двойной клик в Hierarchy — фокус,
  Del — удалить, Ctrl+D — дублировать, Ctrl+S — сохранить, Ctrl+Z / Ctrl+Y — отменить / вернуть,
  Esc — снять выделение. X — оси гизмо мировые / локальные, F2 — переименовать, Ctrl+G — сгруппировать,
  Ctrl+C / Ctrl+X / Ctrl+V — копировать / вырезать / вставить.
- Play: Ctrl+P — запуск / стоп, Ctrl+Shift+P — пауза, Ctrl+Alt+P — шаг на кадр. В виде Game клавиши и мышь
  идут в игру; на паузе и в виде Scene действует всё управление редактора.

## Что не сделано и не проверено

- Перетаскивание (Hierarchy, Project → сцена, объект → Project) проверено только программными событиями.
- Полёт камеры и клавиши проверены программными событиями, не настоящими мышью и клавиатурой.
- Стартовый экран (`Welcome`), Save As, Del, Ctrl+D, вложенные префабы — написаны, вживую не проверялись.
- Добавленное и убранное в экземплярах проверено программно на `iso` (добавить, изменить и убрать компонент;
  добавить объект под объектом префаба и под экземпляром, изменить, переименовать, дать ему ребёнка, удалить;
  убрать и вернуть объект префаба; перенос объекта в экземпляр и обратно событиями перетаскивания; Play; undo;
  Apply All в файл префаба; `check` на файле с ошибками и рендер сцены, написанной руками) и снимком
  Hierarchy. Не проверено: настоящей мышью, вложенные префабы (путь внутрь экземпляра другого префаба),
  добавленный объект, который сам экземпляр префаба, режим редактирования префаба, гизмо на добавленном
  объекте. Перенос под объект с неравным масштабом и поворотом искажает объект (как и вне префабов).
  Порядок добавленных детей относительно детей префаба не меняется: они всегда после. Щелчок во вьюпорте по
  добавленному объекту выбирает экземпляр. После правок состава экземпляра сцена пересобирается целиком.
- Переопределения в экземплярах: Apply — два шага undo (первый возвращает переопределение экземпляру, второй —
  прежний префаб). Другие
  экземпляры со своим переопределением того же поля его сохраняют. Объекты адресуются именами: одинаковые имена соседей в префабе и `/` в имени не поддержаны, после
  переименования в префабе переопределение «повисает» (`check` это ловит, редактор молча пропускает).
  Проверено программно (методы store, Play, undo, revert, unpack, Apply нажатием кнопок, `check` на ошибочном
  файле) и снимком Inspector с пометками; настоящей мышью, гизмо на внутреннем объекте и вложенные префабы
  не проверялись.
- Play проверен программно (нажатие кнопок и шаги `tick` из консоли) и снимком экрана, глазами движение
  во вьюпорте не смотрели.
- Пальцы, геймпад и захват мыши (11.10.2026) проверены только программно в Play на сцене `ui`: два пальца
  (второй держит кнопку, `held`, щелчок по отпусканию, съехал с кнопки — щелчка нет), мышь после пальца снова
  подсвечивает кнопку, `setPad` (кнопка как клавиша, стики, мёртвая зона). Настоящего телефона, настоящего
  геймпада и настоящих событий касания не было. Захват мыши в панели браузера не включился (после
  `lockPointer()` и настоящего щелчка `pointerLocked` остался `false`) — то ли панель его не даёт, то ли
  ошибка; проверить в обычном браузере. Что стоит знать: у геймпада нет вибрации и второго игрока (только
  первый подключённый); раскладка кнопок — «обычная» по версии браузера, у нестандартных геймпадов номера
  другие; жестов (щипок, свайп) нет; первый палец всегда ещё и мышь — если по щелчку стреляют, выстрелит и
  палец на экранной кнопке (`game.ui.overButton` в `self` не выведен).
- Ввод проверен программными событиями клавиш и настоящим кликом мыши; настоящая клавиатура в идущей
  игре не проверена. Нет захвата указателя (pointer lock), геймпада и касаний.
- Поведения: объекты, созданные в игре (`self.spawn`), показаны в Hierarchy отдельным списком только для
  просмотра (щелчок — фокус камеры; выбрать и править их нельзя) и после Stop исчезают;
  объект, добавленный в сцену в обход `spawn` / `Runtime.add` (просто `root.add(...)`), свои поведения не
  запускает. Нет поиска объектов и поведений по всей сцене, кроме `root.getObjectByName`.
  Столкновения: куб по осям мира, шар и вертикальная капсула — без наклонных и своих форм; нет настоящей
  физики (толчков, отскоков, вращения), гравитация только через `self.fall`, без ступенек и склонов; объект
  тоньше 0.25 м на большой скорости всё ещё может проскочить; все пары проверяются перебором
  (для сотен коллайдеров будет медленно); объекты внутри экземпляра префаба получить коллайдер могут
  только в самом префабе. Проверено программно в Play на `iso` (упор в стену, скольжение, монета-триггер,
  выход из застревания, капсула и сдвиг центра); ручки Edit Collider — настоящей мышью (сторона, верх и
  середина куба), у шара и капсулы только что ручки появляются; настоящими клавишами не играли. Проверено программно в Play (шаги `game.update` из консоли: `spawner` с пределом, `lifetime`,
  `get`, хук `destroy` при удалении); в собранной игре и глазами не смотрели.
- Поверхности: «плывущих» текстур PS1 нет (в материалах нет текстур). Тени и проход глубины для сетки и
  маркеров рисуются без сдвига вершин — при `sway` или крупном `vertexSnap` сетка и тени расходятся с
  объектами. `toon` считает свет по готовому цвету (яркость / яркость материала), а не по каждому источнику;
  `range` подбирается под свет сцены руками. Проверено в редакторе снимками экрана (PS1, toon + flat + контур,
  `sway`, смена чисел после выключения и включения стиля); в Play и в собранной игре не смотрели. Кнопки
  списка Surfaces в Inspector (добавить, убрать, переставить) мышью не нажимались. С перспективной камерой при движении
  пиксели «кипят» — привязка есть только у ортографической; при повороте ортографической камеры и у
  движущихся объектов кипение остаётся; на краю экрана при привязке возможна полоса повторённых пикселей
  шириной до одного пикселя картинки. Привязка проверена измерением (два кадра `iso` со сдвигом камеры
  меньше и больше пикселя: с привязкой отличаются десятки пикселей из полумиллиона, без неё — тысячи),
  глазами в движении не смотрели. Край заслонения сетки и маркеров чёткий, а силуэты в картинке
  крупнопиксельные — на стыке возможен зазор до размера пикселя. Ошибки шейдеров в редакторе видны только в консоли браузера (из командной строки их показывает `npm run render`). Перестановка эффектов, добавление из
  меню и перетаскивание Look в сцену мышью не проверялись. Вид из выбранной камеры и Play с ортографической камерой проверены снимками.
- Лучи, поиск, гравитация, слои и теги проверены программно на сцене, собранной в тесте (попадание в куб, шар и
  капсулу сбоку и сверху, опции луча, луч с экрана, падение и прыжок, упор в тонкую стену одним длинным
  сдвигом, проход сквозь слой из `noCollision`, монета не подбирается при выключенной паре и подбирается при
